## v2 — 全局化 + 学习闭环 (forge-core 已落地,持续推进)
**forge-core 已存在、已构建、全绿**:纯 Go 标准库、**零外部依赖**(`go.mod` 无 `require`)。CLI 已覆盖 `run/evolve/init/trace/approve/reject/preflight/doctor/gate/check/accept` 等；`forge run --chain` 持久化跨阶段状态并执行 Discover→Design→Review→Build→Deploy→Evolve，`forge evolve` 按真实 stop signal 收敛。产物 JSONL v1 记录 run/workflow/phase/agent/model/hash，planner/审批/拒绝/CTO halt 均有机器契约；Rust/Java adapter 与 init/upgrade copy-anywhere 已接入验收。
- [x] **Rust Agent Runtime 首切片(ADR 0006)**:`forge-runtime/` clean-room 实现单一模型/工具循环、版本化 JSONL 事件、turn/tool/output 硬上限、能力检查、workspace 内只读工具与 deterministic provider；全程离线,不调用真实 LLM。
- [x] **Local-first Conversation Hub(ADR 0007 + 0009)**:CLI 无路径进入 Global、有路径/`-C` 进入 Project、`--group` 进入 Group；SQLite 跨进程持久化 Project/Conversation/Prompt 与 frontend/backend/SSO 等带角色标签的联动。`group context` 能在单一 SQLite 快照中生成有界、因果有序、带来源和 SHA-256 摘要的 Group/member-Project Prompt dossier，默认不显示正文且绝不读取项目文件；`group run prepare/show/list` 进一步把 exact dossier 原子冻结为独立 prepared Group Run，同幂等键重放旧字节而不查询最新历史，也不启动 provider/tool/workspace。Prompt 仍由调用者显式追加；Project Run 会以所选 user Prompt 为边界注入严格 512 KiB 的既有 user/assistant 历史。远程账号/同步、共享 ACL 与多 Agent 组执行继续分期。
- [x] **Local Group execution integrity receipt(ADR 0010)**:`group execution start/show/list` 把已验证 prepared Group Run 绑定到独立 SQLite v4 execution，持久化有界三事件证据与 content-free receipt；同 key 跨进程重放终态，或仅为合法 incomplete 前缀补确定性 suffix。该同步管理路径不构造模型/provider/runtime/workspace/tool/network，不创建 Project Run/assistant Prompt，也不把 integrity validation 冒充分析、讨论或任务结果；单模型消费由下项 ADR 0011 的独立边界接续，multi-Agent execution 仍属后续。
- [x] **Two-phase Group model analysis(ADR 0011)**:`group analysis prepare/show/list/send` 在 SQLite v5 中把一份已验证 frozen dossier 绑定到精确、零工具、`store:false` 的 Responses 请求。prepare 纯本地且原子；send 要求当次显式外发同意并在 claim 前完成凭证/目标预检，只有 claim 赢家取得 exact body 并至多发送一次。claim 后任何不确定错误都禁止自动重发；仅真实完整 terminal 可原子落库，默认输出隐藏请求、事件和结果正文。它是单模型分析，不冒充 multi-Agent 讨论、事实认证、工具执行或 Conversation memory。
- [x] **Durable local Group analysis panel(ADR 0013)**:`group panel prepare/show/list` 在 SQLite v6 中把同一 exact Group Run 的 2–8 份 terminal-completed 分析按调用者顺序冻结为 canonical manifest；同 key 精确重放，变更来源、结果或顺序即冲突，`length` 不可入组。默认隐藏结果正文，显式查看也会重验 Group Run、源分析、member rows、canonical bytes 与 digest；整个路径无 provider/凭证/网络/workspace/tool/Conversation/task/memory 副作用，且只声明本地并排组装，不冒充讨论、综合或共识。
- [x] **Two-phase Group panel synthesis(ADR 0015)**:`group synthesis prepare/send/show/list` 把一个 exact panel 的 canonical manifest 固定为唯一 user message，原子持久化零工具、`store:false` 的 exact request；每次 send 都需新的 off-machine consent，claim 前重验 panel/源结果/目标/字节，只有单赢家获得 request authority，claim 后不自动重发。结果诚实标记为 single-model synthesis，不冒充讨论/共识/事实验证，也不访问 dossier/workspace/tool 或写回 Conversation/task/memory。
- [x] **Durable local Group Agent Graph(ADR 0017)**:`group graph prepare/show/list` 把一个 exact frozen Group Run、manager 标签/指令、1–32 个绑定 frozen `project_id+role` 的 Agent task、dependency edges 与 authored-order deterministic waves 冻结为 SQLite v8 immutable manifest。同 key 只重放完全相同的 semantic graph，默认隐藏 spec，显式查看会重验 source/member/canonical bytes/digest；本切片只生成执行图，不运行 manager/node、不访问 provider/network/tool、不扫描 member workspace（只可读取 caller 明示的 spec file），也不写回 task/memory。
- [x] **Core-owned passive Graph Run plan(ADR 0018)**:`forge graph-plan` 把 workflow 与 Group Graph 收敛到同一个 authored-order dependency 实现，并输出跨 Go/Rust 共用 golden 锁定的 canonical Core Plan。`group graph run prepare/show/list` 在 SQLite v9 被动校验并冻结 exact Graph/manifest/plan 与唯一 preparation event；状态固定 `awaiting_execution_contract`，execution-contract/dispatch-authority 永远为 false。本切片不选择 next wave、不 claim node、不运行 manager/node/model/tool/workspace，也不产生 result/writeback。
- [x] **Core-owned first-node execution contract(ADR 0019)**:`group graph run control export` 输出 exact private v1 control snapshot；`forge graph-node-contract` 唯一选择 `plan.waves[0][0]`，冻结 Prompt、provider/model、预算、零 workspace/tool/dataflow 与 no-retry policy；`contract admit/show/list` 在 SQLite v10 以 seq/head CAS 原子登记唯一契约并把 Run 推到 `awaiting_core_dispatch`。dispatch authority 仍为 false，未读 credential、未调用 model/provider/Agent、未访问 workspace/network/tool，也未产生 result/writeback。
- [x] **Core-owned Node Dispatch Request preparation(ADR 0021)**:`group graph run dispatch prepare/show/list` 只用现有 Responses 纯 codec，把已 admission 的 first-node logical request 确定性编码并在 SQLite v11 原子保存 exact bytes、content-addressed identity 与 seq-3 receipt；Run 停在 v3 `awaiting_dispatch_authorization`。默认输出隐藏 body/Prompt/endpoint/model/pricing，只有显式 `--include-request` 揭示 exact body；整个路径不收集 consent、不读 credential、不构造 provider/transport、不访问 network/workspace/tool，也不产生 result/writeback 或调度后继。
- [x] **Effect-free Node Dispatch release authorization(ADR 0022)**:`dispatch release-control export` 从完整重验的 v3 source/contract/seq-3 head/exact request 导出 private canonical snapshot；`forge graph-node-dispatch-authorize` 由 Go 独立重建 base control、request 与全部 scheduler binding，并生成绑定 exact bytes/head/lane/budget/failure policy 的 content-addressed authorization；Rust `dispatch authorization verify` 再对当前 durable state 独立复验。schema 仍为 v11、Run 仍为 v3，authorization 不落库且 authority/consent/credential/provider/network/lane/result/writeback/advance 均保持 false。
- [x] **Strict Hub schema ownership validation(ADR 0012，ADR 0013/0015/0017/0018/0019/0021 延伸)**:每个 v0–v11 声明版本在任何迁移 DDL 前先按不可变 DDL 复验（v0 必须空 catalog），迁移提交前再复验完整 v11 的 24 张表、20 个显式索引、45 个隐式 autoindex exact/structural 契约与独占 main catalog。旧 CHECK/PK/UQ/FK/index 漂移、额外 table/view/trigger/virtual shadow 均失败关闭且不自动修复，迁移末端失败整链回滚。
- [x] **Durable Project Run + Responses adapter(ADR 0008)**:SQLite v1→v2 追加执行配置、增量语义 cursor、同快照 inspection、`runs`/`run_events`/Run-assistant 关联，persistence-first sink 保证 `tool_started` 在工具效果前提交；`run start/list/show`、bounded causal history、terminal/incomplete/pending-tool 判定、原子 assistant 写回与终态 crash-repair 均已交付。默认 deterministic/offline；显式 `--live` 默认零工具，仅 exact `--allow-read` 授权，并启用固定 HTTPS origin、无 redirect/隐式 retry、`store:false` 完整 output-item 回放、phase-aware final projection、terminal identity/status 校验及完整传输/token 上限；incomplete 永不释放工具。自动 execution resume、写/进程工具、remote 与 Web 不在本项。
- [x] **声明式生产交付边界(ADR 0005)**:Deploy/Rollback 使用精确 emit 权限、固定最小 prompt、operator-pinned Claude executable bytes(非供应商身份)、整树 postflight、严格 JSON/verdict、validation receipt 与 source/artifact freshness；人审 marker 才能推进，远程执行保持外置。
- [x] **Durable lifecycle-driven migration(ADR 0016)**:`forge migrate --to-lifecycle production [--apply]` 只把显式持久晋升事件映射到 production；Explorer 同事务迁为 Engineering 并稳定注入五项补债，其他已知 mode 只改 lifecycle，已 production 不追溯。manual/lifecycle 共用 run lock、canonical intent WAL、before-image CAS、独立 receipt 与确定性 roll-forward；dry/transient flags 零写入，run/evolve 双检 terminal receipt 形成不可静默降级的持久治理 floor，status 暴露 pending/operation/recovery。
**明确遗留缺口(诚实标注,不夸大):**
- Agent 阶段默认 dry-run(`DryRunExecutor` 只叙述,安全默认);真实执行器需显式 `--executor command`。Claude prompt 走 stdin，子进程环境最小化；额外变量须 `--agent-env` 精确授权。未经本轮用户授权不重复烧付费模型预算。
- 原生 Go YAML 子集解析器为主，`harness/yaml2json.py` 仅作兼容回退；未知格式/契约版本均失败关闭。
- 独立 `agent-os` 仓库仍按 ADR 0003 等待远程位置与批准；Web UI/完整多厂商 Router 属 v3。Firecracker runner 与跨厂商 LiteLLM 验证受当前主机能力/第二厂商凭证阻塞，详见功能审计。
- 远程部署/回滚是明确非目标：ForgeOS 只生成和验证声明式交付包，外部 CI/operator 实施并由人写结构化 approval marker；command-mode release 当前因开放 FD pin 契约只支持 Linux，其他平台失败关闭。

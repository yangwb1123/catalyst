# Skill: modularization

> 单体 → 单一职责模块的通用法则。One module, one reason to change.

## 目标 (Goal)
把一坨耦合代码拆成边界清晰、低耦合高内聚的模块,每个模块只有**一个变更理由**。

## 触发条件 (Triggers)
- 一个模块/文件承担多个职责或多个变更原因。
- 跨领域逻辑纠缠;改一处波及无关功能。
- 命中体积/复杂度阈值(见 skill: refactor-large-file),需结构性拆分而非局部抽函数。

## 步骤 (Steps)
1. **找接缝 (seams)**:沿业务能力 / 变更轴划边界;一个模块 = 一个职责。
2. **定契约 (contract)**:每模块暴露**最小公共接口**;实现细节私有,禁止穿透内部。
3. **依赖倒置 (DIP)**:模块依赖抽象(interface/port)而非具体;依赖由外部注入,不在内部 new。
4. **内聚检验 (cohesion)**:模块内元素应高度相关;否则继续拆。
5. **解耦 (decouple)**:消除双向依赖与隐式全局状态;跨模块只经公共接口通信。
6. **组合 (compose)**:用组合而非继承拼装;禁止 God Object。
7. **验证**:单元测试可对单模块独立运行(无需启动全系统);`node harness/gate.mjs` 循环依赖 = 0。

## 法则 (Rules)
- 单一职责 (SRP)、高内聚低耦合、组合优先、显式依赖、稳定接口/易变实现。

## 输出 (Output)
- 模块清单(`模块 → 职责 → 公共接口`)。
- 依赖图(确认单向、无环)。
- 各模块独立单元测试结果 + gate verdict。

# ForgeOS — Decisions

## 已锁定(默认,可推翻)
- **D1 技术栈**:**目标 = Go-核心 polyglot**(`forge-core`=Go 编排/调度/路由/workflow · `forge-ai`=Python 智能层 · `forge-runtime`=Rust Agent Loop + Conversation/Run 持久化 + 沙箱边界 · `forge-web`=TS/Next UI)。**时序**:v0–v1 不写 forge-core——编排=Claude Code 本体,只写声明式 agent 卡/workflow/policy + 薄胶水(`gate.mjs` 现用 Node,够用)+ polyglot harness 适配器。**Go 已在 v2 进入**(见 D6);用户于 2026-07-27 提前授权 Rust 的离线 Agent Loop(ADR 0006)及 local-first Conversation Hub(ADR 0007)首切片。SQLite Project/Conversation/Group/Prompt ledger 已落地；真实 provider、自动历史回放/Run 恢复、远程账号同步、写工具与生产沙箱仍按后续阶段推进。Temporal/Postgres/NATS 仍未起。harness CLI 未来固化为 **Go 静态二进制**(目标仓零运行时依赖)。
- **D6 v2 forge-core 启动 (2026-06-19)**:核心循环已在 CC 上经 `examples/url-shortener` dogfood 端到端验证稳定(architect→3 implementer→fresh reviewer→fix,被 `forge accept` 实际 gate)→ 触发 ADR-0001 的取代条件,**正式开建自研 Go 运行时 `forge-core`**。启动时 7 包；当前 `go list ./...` 实测 61 包（59 internal + `cmd/forge` + 独立非 Agent `cmd/forge-kernel`；排除 test-only `internal/adr` 后产品包 60），仍为纯 Go 标准库、**零外部依赖**。CLI 已扩展到 run/evolve/init/trace/approve/reject/preflight/doctor/gate/check/accept 等，含 durable chain、产物/审批/拒绝契约与多语言验收。gate 阶段执行真实 harness；路由带硬 Opus 底线；`forge evolve` 的收敛由 live signals 实算。**诚实边界**:agent 阶段默认 dry-run / 不调 LLM；真实执行器须显式 `--executor command --agent-cmd claude` 并具备 CLI、凭证与预算。workflow 先由原生零依赖 Go YAML 子集解析器处理，Python shim 仅为兼容回退。ADR-0001 据此置 Superseded。
- **D7 生产交付边界 (2026-07-27)**:采纳 ADR 0005。`deploy`/`rollback` 只生成、验证并由人批准声明式 `docs/release` 交付包；不持有生产凭证、不执行远程动作。release command 使用最小固定 prompt、精确 emit 权限、operator-pinned Claude executable bytes(非供应商身份)、receipt/source/artifact freshness 与 durable human marker；远程应用始终归外部 CI/operator。
- **D8 ai-batch-runner clean-room 借鉴边界 (2026-08-03)**:参考树当前 ahead 15 且有 21 个 tracked changes/16 个 untracked paths，README 明示来自另一 monorepo 且未选 license；因此只审计可观察行为，不复制代码、测试、Schema、Prompt 或文字。采纳其「effective-input fingerprint resume + explicit fail-closed gate」原则并以 Catalyst 自有 canonical/content-addressed 协议落实到 ADR 0028；拒绝 corrupt JSONL skip、PID/file-lock authority、环境变量/TTY approval bypass、blanket provider retry 与 implicit git mutation。ADR 0028 的 schedule-bound authorization 与 ADR 0030 的 ordinal-zero fresh-preflight/claim/one-shot-terminal 生命周期当时已完成；当时尚未授权的多节点 successor 与本地 hard-crash adjudication 后续已由 ADR 0031–0036/v17–v24 交付，remote sync 仍未授权。
- **D9 能力中心化 AI Engineering OS (2026-08-08)**:采纳 ADR 0037。组织不按 Agent 数量扩张，而按「00–16 生命周期决策节点 × 可复用 Capability/Skill × 显式 CapabilityGrant」装配临时 Agent；先建 Evidence/Claim/Context/Permission Governance Kernel，再建可重建 Knowledge Graph 与 Impact/Cost/Risk，之后才扩角色 Skill、Debt/Health、Review/Evolution。`.agent` 保持可执行主干，`docs/reviews`/`docs/ai-batch` 经 canonical registry 渐进适配，不另建第二 DAG/第四套平行体系。该目录的目标态与未勾选路线仍是 planning-only；ADR 0040–0056 已采纳的合同切片按各自决策边界生效，implementation 状态以 roadmap/gates 为准，不得冒充完整 runtime，远程生产 effect 边界不变。
- **D10 AADM + Meta Reflection (2026-08-08)**:采纳 ADR 0038。Atom/DecisionTransaction/InteractionEvent/Capability/Artifact/receipt 构成目标 Kernel ABI；规则场先过滤硬约束，再以多目标/最低充分复杂度和裁量包络做滚动规划。Node16 每次 R0、L2 R1、L3/L4 R2 evidence-first 纠查，知识/规则/Eval/ADR/Debt/后续工作一律 proposal-first。ADR 0047 已交付七类 KnowledgeClaim→CognitiveAtom 的确定性纯 shadow 投影，但完整 Atom/DecisionTransaction/InteractionEvent/Capability/Artifact/receipt ABI、solver、Registry、Controller 与 Reflection runtime 仍未实现。
- **D11 Default-off Device Fabric (2026-08-08)**:采纳 ADR 0039。Logical Agent、Task、Attempt、ExecutionTarget 分离；先以 LocalExecutionTarget 冻结接口，再逐级 Inventory/Observe、结构化 SSH、mTLS Runner/Lease/Fencing、Placement/Reconciliation、safe migration，Federation 最后。所有远程模式默认关闭，LOST/未知 effect 不自动重试，Fabric 不取得生产权限；当前本地 runner 不等于远程 Fabric 已实现。
- **D12 Machine-readable Agent Engineering 规范 (2026-08-09)**:采纳 ADR 0040。根 `AGENTS.md` 保持短入口，`.agent/engineering` 承载 activation、14 学科、原子规则、载重 detector、typed Context 路由和 W0–W3 保障覆盖层；TaskEvidencePackage 只封装 source-bound 观察且禁止自写完成裁决。严格 validator 随 `forge check`/scaffold/upgrade 执法，旧项目缺显式绑定时使用 shadow 默认。当前只证明合同、引用与接线，不冒充 Context Router、Capability Registry、AADM/Reflection runtime；`forge accept` 仍是唯一完成权威。
- **D13 Backend decision + persistence gate (2026-08-09)**:采纳 ADR 0041。后端变更按 16 类风险触发 L1–L4/W1–W3 floor，并使用 14 维 BackendDecisionPackage；持久化身份/约束/历史/访问路径/并发/迁移必须先于 ORM，DTO/Command/Domain/Persistence/Read/Response/External 仅按 owner、变化原因和安全边界条件化分离，禁止机械六层化。十张密集 Skill adapter 与 security/data/backend Context route 已验证并随 scaffold/upgrade 继承；policy/Schema、逐项有界仓库文件、proof type/class/subject、readiness dependency、ADR/Reviewer 关系均被校验。完整 tree/context provenance 和受信 producer/reviewer attestation 仍待 runtime；detector 保持 shadow、无完成/批准权，真正 pre-code fail-closed 仍等待 Evidence/Claim/Context/Grant runtime。
- **D14 Frontend design decision contract (2026-08-09)**:采纳 ADR 0042。前端改动按场景、风险和变化半径触发 L1–L4/W1–W3 floor，并以 14 维 FrontendDesignPackage 在编码前区分业务任务、IA、flow/state/action/permission、Profile×Pattern、Design Token、跨平台语义、无障碍、动效/性能与验证证据。CMS/OA/ERP/CRM/Analytics/Commerce/Marketing/Immersive/Data Wall/AI UI 等是 Profile，React/Vue/Flutter/RN 是 target adapter；固定字号、断点、8pt 和视觉分数不得冒充通用标准。三张 canonical Skill、Context route、shadow detector、对抗 validator 与 scaffold/upgrade 已接入；截图/trace 字节可校验但 producer/reviewer 身份仍是声明，最终完成只属于 `forge accept`。
- **D15 Frontend code architecture governance (2026-08-09)**:采纳 ADR 0043。增加独立 `frontend-code-architecture` procedural Skill，但不新增 fine capability 或改写 frontend-client/architecture/review/refactor 的主 ownership。项目通过 `.arch/frontend-architecture.v1.json` 显式选择 target、模块所有权、layer allowlist 与 public/test entrypoint；TypeScript/TSX 使用项目 Compiler API，Vue/Dart 未有 adapter 时必须 inconclusive。方向、所有权、循环和配置完整性不可 baseline/waive；行数、Hook/state/effect、目录与 API 预算只作 review signal，God 结论需多信号和独立语义证据。detector 保持 shadow/non-load-bearing，完成权威仍仅 `forge accept`。
- **D16 Business UI geometry contract (2026-08-09)**:采纳 ADR 0044。`ui-geometry` 是条件化 supporting procedural Skill，不是第四个 AFDS capability owner；信息/交互、Design System/无障碍和客户端实现仍由既有三张 canonical Skill 负责。FrontendDesignPackage v1 顶层 ABI 不变，layout decision 以 exact `business_ui_composition` proof 绑定 digest-pinned composition source artifact；项目真实 Runner 可另附 `geometry_measurement_receipts`，但 report 只是绑定 source/build/fixture/environment/runner/原始观察和 policy 结果的声明式执行观察。当前 validator 只校验有界 JSON、引用、摘要与语义一致性，不执行浏览器/原生平台，不裁定视觉平衡、光学校正、任务成功或可信来源；fail/inconclusive/not-executed 不得被分数掩盖，完成权威仍仅 `forge accept`。
- **D17 Canonical Evidence/Claim shadow kernel (2026-08-09)**:采纳 ADR 0045。Wave 0F-A 只交付 strict `EvidenceRecord`/`KnowledgeClaim` v1、record/aggregate/sequence identity、kind-separated canonical SHA-256、状态矩阵、authority-free shadow admissibility 和 Go/Rust/Python exact golden。候选记录只可得到“结构有效”结果，不认证 producer/collector/reviewer，不确认事实、不接受决策、不满足 hard gate，也不写 Hub、导入旧 Memory/ADR、签发 Grant/Approval 或推进 Transition；完整 ledger、Context、authority、replay/revocation 与 SoD 保持后续边界。
- **D18 Local GovernanceRecordJournal (2026-08-09)**:采纳 ADR 0046。Wave 0F-B–1 仅允许在本地 SQLite v25 中原子追加 exact Evidence/Claim v1 record set，以 domain-separated request/batch identity、caller idempotency、immutable bytes、连续 predecessor、原始 receipt replay 和 rebuildable structural head 保持结构历史；默认 inspection 不返回 record 正文。引用闭包冻结为最多 1,024 dependency records、16,777,216 candidate+closure bytes 与 256 derivation edges，且只作为防资源耗尽的 admissibility limits。Receipt 只能为 `stored|exact_replay`，head 只能解释为 `structural_sequence_only`。Scaffold 不安装 `forge-runtime`；缺兼容 binary 时 persistence 必须 `not_executed`。Rust domain/application/store、SQLite v25、CLI、migration/compatibility 与对抗验证已完成，并经独立复审和 `forge accept` 验收；该切片永不认证身份、不确认事实、不解释 freshness/conflict/lifecycle、不接受决策、不写 knowledge、不授予 authority 或完成权。
- **D19 Shadow CognitiveAtom projection (2026-08-10)**:采纳 ADR 0047。`forgeos.aadm.cognitive-atom/v1` 只把经 ADR 0045 重新验证的 exact canonical KnowledgeClaim record set 中 `fact|constraint|decision|inference|assumption|hypothesis|unknown` 七类声明确定性投影为 CognitiveAtom；`lesson|proposal` 只可作引用闭包成员，不生成 Atom。唯一正结果为 `PROJECTED_SHADOW`；它只证明 pure reprojection 的字节、identity、digest 与 source closure 一致，不证明 truth/authority/instruction/hard guard/transition/completion/effect，不写 GovernanceRecordJournal/SQLite 或其他持久化，也不实现 prompt/model compiler、journal adapter 或完整 Kernel ABI。
- **D20 Artifact provenance Evidence adapter (2026-08-10)**:采纳 ADR 0048。`forgeos.governance.artifact-evidence-adapter/v1` 只接受 exact compact canonical request，其中 artifact 必须明确为完整十一字段 `forgeos.artifact.v1`，Governance identity/context/policy/tree/subject/sequence/sensitivity 由调用方显式 binding；artifact source 与完整 request 分别使用 domain-separated SHA-256，确定性生成既有 strict `EvidenceRecord` v1。Python、Go、Rust 独立实现与 Universal checker 共用 exact golden，唯一正结果为 `ADAPTED_SHADOW (no truth, authority, claim, atom, persistence, or effect attestation)`。adapter 不读取当前 artifact 文件，不认证 manifest、agent/model 或 collector，不创建 Claim/Atom，不 append journal、不写数据库或产生 effect；SQLite 保持 v25，且无 migration/backfill。
- **D21 Command observation Evidence adapter (2026-08-10)**:采纳 ADR 0049。`forgeos.governance.command-observation-evidence-adapter/v1` 只接受 exact compact canonical request，将 direct-exec argv、normalized cwd、opaque environment/tool/source-tree digest 声明、producer/run、整数毫秒时间、真实 exit 与 full/retained stream 摘要绑定到显式 Governance identity。command、observation、request 与既有 strict EvidenceRecord 使用独立 digest domain；Python、Go、Rust 和 Universal checker 共用 exact golden。Observation 可表达 exited/timeout/cancel，但 adapter 只无损投影真实 exited，禁止负 sentinel、signal/spawn 猜测；唯一正结果是 `ADAPTED_SHADOW (observation mapping only; no execution, pass, completion, truth, authority, claim, atom, persistence, or effect attestation)`。它不执行命令、不验证 stream preimage/producer/digest profile、不把 exit=0 当 PASS、不 append journal 或写数据库；SQLite 保持 v25，无 migration/backfill，真实 command producer 接线仍须另行版本化，Evolve locator adapter 已由 D22/ADR 0050 独立交付。
- **D22 Evolve repository locator Evidence adapter (2026-08-10)**:采纳 ADR 0050。`forgeos.governance.evolve-repo-locator-evidence-adapter/v1` 只接受 caller-declared exact `forgeos.evolve-repo-locator/v1` observation 与显式 Governance binding，把 repo-relative path、line/detail、完整文件 content digest/bytes、scan contract/dimension/depth/relation/opportunity/report digest、producer/run/time 和 source revision/tree 声明确定性映射为既有 `repo_locator` EvidenceRecord。locator、observation、request 与 Evidence 使用分离 digest domain；Python、Go、Rust 和 Universal checker 共用 exact golden。adapter 不读取当前 repository path/report，不解析 symlink、不验证 file/report/tree/parameters digest preimage，不确认 finding/clear/opportunity、扫描完成或 Evolve candidate，不认证 producer，不创建 Claim/Atom，不 append journal、不写数据库或产生 effect；唯一正结果是 `ADAPTED_SHADOW (locator mapping only; no file/report verification, scan judgment, completion, truth, authority, claim, atom, persistence, or effect attestation)`，SQLite 保持 v25且无 migration/backfill，真实 Evolve producer 接线另行版本化。
- **D23 Local gate command observation producer (2026-08-10)**:采纳并交付 ADR 0051。`forgeos.governance.local-gate-command-observation-production/v1` 只允许在 canonical Git 根目录 direct-exec 四个固定本地命令：`node harness/gate.mjs`、`python3 harness/check.py .`、`node harness/acceptance.mjs` 与 `node harness/acceptance.mjs --json`。producer 固定为 `forgeos.local-gate-command-observer`，以独立 domain-separated digest 绑定实际 scrubbed child environment、PATH-resolved top-level executable/symlink/file bytes、bounded-interval Git inventory+entry source observation、raw streams 与 termination；默认 gate path 仍关闭 capture。source scan 不是原子快照或 execution pin，producer 也不提供 sandbox/effect containment。Go/Python/golden/scaffold/对抗测试、完整 gate 与两份独立 CLEAN 复审已完成；输出只声明 `OBSERVED_LOCAL_PROCESS`，不得把 exit=0、stdout、manifest 或 source revision 解释为 PASS、criterion、completion、truth、authority、identity、persistence 或 external effect。
- **D24 Local Evolve locator observation producer (2026-08-10)**:采纳并交付 ADR 0052。显式 opt-in、Unix-only producer 绑定完整 canonical `EVOLVE_SCAN_V1: ` report preimage、共享 `git-worktree-source-tree-v1` 的 bounded-interval 非原子 source observation，以及按 dimension/relation/opportunity/report 顺序产生的 zero-or-more locator；同 path 跨 relation 出现必须保留，不能去重。它只运行固定 read-only Git subprocess；不认证 Git binary，不提供 sandbox/egress/effect containment，不确认扫描 judgment/completion/truth/authority，不产生 Claim/Atom/持久化，且不自动调用 ADR 0050 adapter。Schema、exact golden、strict Python checker、Go producer、governance/Skill/scaffold、对抗测试与独立 CLEAN 复审已接线；交付状态不扩大上述非能力边界。
- **D25 Local Go package dependency graph observation producer（2026-08-10，DONE）**:采纳并交付 ADR 0053。显式 opt-in、Unix-local producer 只对共享 bounded-interval source 中按 `selected-module-all-regular-go-files-union-v1` 选择的 `.go` 文件做标准库语法解析，记录 package/module nodes、compile/test dependency edges、external/unresolved refs、coverage 与 diagnostics；它不运行 Go toolchain、不解析真实 GOOS/GOARCH/build tags/module cache/workspace replacements，不证明 build/test/runtime reachability、graph completeness、architecture 或 change impact，也不生成 Evidence/Claim/Atom/Context/Grant/Impact/Cost/Risk、不持久化或产生 effect。Registry v10 将 ADR 0051/0052/0053 同列 `shipped_producers`，`staged_producers` 为空；两份独立 fresh-context 复审 CLEAN，最终完成权威仍只来自实际 `forge accept`。
- **D34 Local Go Package ImpactPreScan（2026-08-12，DONE）**:采纳 ADR 0062。Pure local evaluator 只消费 exact ADR-0053 graph bytes/digest/run ID 与严格 sorted changed paths，重建 package/node/edge identity、seed partition、反向 local-edge fixed point、完整 induced edges 和 deterministic shortest witnesses；package closure 对任一 path/diagnostic/resolution gap 失败关闭为 UNKNOWN，system impact 永远 UNKNOWN。它不隐式捕获 repo、不运行 Go toolchain、不提供 selected build/System Knowledge Graph/final Impact/Cost/Risk/Assessment、truth/authority/completion/persistence/effect。
- **D35 L3/L4 Build Reviewer strict verdict（2026-08-12，DONE）**:采纳 ADR 0063。仅 caller-declared L3/L4 Build 把唯一 `reviewer_v1` 提升为 required，并对缺失/畸形 verdict、跳过、并行与不兼容恢复失败关闭；L0–L2/未绑定保持旧 advisory 兼容。声明没有 classification authority；role/model/provider identity、review quality、cryptographic SoD、source/context/artifact digest binding 与 same-UID state tamper resistance 均未交付，旧 runtime 对 unknown contract 必须拒绝。
- **D36 Local digest-bound Agent output/review/approval（2026-08-12，DONE）**:ADR 0064 的 A–D 已整体交付。七个 canonical workflow 以 `output_binding_contract: local_digest_v1` 选择 accepted command-output receipt；L3/L4 Build 使用不原地扩展 `reviewer_v1` 的 `reviewer_v2` challenge echo；Design/Deploy/Rollback positive approval 只引用 current ApprovalContext；checkpoint/chain v5、claim/receipt heads 与 exact semantic restore 防止恢复降级。四者绑定 runtime-computed product source、exact prebinding prompt context、完整 effective local policy与 declared artifact manifests。Receipt/context/marker 仍只是 same-UID local observation/control reference，不是 ADR-0059 ApprovalRecord、identity/SoD、signed PDP/Grant、truth、completion 或 effect authority。
- **D37 Authority-free GraphSnapshot v1（2026-08-12，DONE）**:ADR 0065 冻结通用 stable identity、node/edge taxonomy、extractor/source provenance 与 GraphSnapshot v1 基础形状，并交付一个只消费 exact ADR-0053 caller bytes 的 module/package lexical PARTIAL/UNKNOWN projector。Go/Python、CLI、strict reconstruction checker、golden、registry 与 universal scaffold 已接线；未观察 surface、system knowledge 与 freshness 均保持 UNKNOWN。该结果不认证 project/source/observer/projector，不是完整 System Knowledge Graph、Impact/Cost/Risk、G3、Assessment Join、persistence 或 authority；Rust 与多 surface extractor仍未交付。
- **D38 Local Go lexical test-source GraphSnapshot profile（2026-08-12，DONE）**:ADR 0066 采用独立 request/envelope API 和 profile，在 exact ADR-0053 caller bytes 上为每个 `test_files` 非空 package 投影一个 lexical test source-set node 与 module→test `contains` edge；旧 ADR 0065 transport/Schema/golden 不变。Go/Python、CLI、strict reconstruction checker、第二 golden、Skill 与 universal scaffold 已接线；该项交付时 registry 为 v21，现由 ADR 0067 的正交接线提升至 v22。两个 coverage surface 都保持 PARTIAL，system/freshness 保持 UNKNOWN；不解析或执行 tests，不产生 case/result/coverage/verified subject、G3、Assessment Join、Impact/Cost/Risk、persistence 或 authority，Rust与多 surface extractor仍未交付。
- **D39 Proposed-only ADR v2（2026-08-12，DONE）**:采纳 ADR 0067。只为新建 Proposed ADR 冻结 `forgeos.architecture-decision-record/v2` exact document：一行 canonical JSON frontmatter、固定有内容的 Markdown sections、物理文件名/ID/title 绑定和 body/self domain-separated digests。Universal Python checker 只读显式文件或 pinned golden；Go 保留 `writes_adr` 既有 baseline integrity snapshot，但只对 current attempt 唯一新增候选做 v2 验证，旧 ADR 不做 v2 parse、retro-validation 或 migration。owner/approver、Claim/Evidence、affected Graph node 与 implementation refs 都是 caller/author declaration，不认证 identity/SoD/ApprovalRecord/truth/coverage/compliance，不接受或持久化决策，也不实现 immutable/supersession lifecycle 或 effect authority。

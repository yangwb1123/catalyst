# Bundled product-readiness analysis

This guide turns product signals into questions and evidence requirements. It
does not authorize speculative features.

## Reusable module

- Identify the stable caller contract, versioning boundary and ownership.
- Require tests and completion evidence for the supported contract.

## Platform capability

- Confirm tenancy, authorization, audit, API compatibility and integration
  boundaries before implementation.
- Low-cost context fields may be reserved; billing, marketplace and cross-org
  sharing require explicit product authority.

## Product feature

- Confirm target users, measurable outcome, operations/support ownership and
  release/rollback evidence.
- Open-source or commercial packaging is in scope only when explicitly stated.

Questions inferred from authentication, uploads, workflows, messaging, ERP or
search remain `TO-CONFIRM`; they are not implementation requirements.

# ADR-0103: Control Store Journal Foundation v1

## Context
The R0 App Server has a hardened Linux process, state-directory and loopback boundary, while Platform Core v1 provides strict canonical CommandEnvelope and EventEnvelope bindings. The next product step needs durable command idempotency, optimistic aggregate versions and replayable event transport foundations before Space, Objective, Runtime or Harness application services can safely expose mutation APIs.

Opening a database by the configured pathname after taking a descriptor-relative instance lock could separate the lock and database if that pathname is replaced. Treating SQLite tables as a public client API would also couple the CLI, UI, Runtime and Harness to private migrations. This slice therefore establishes only a private Go-owned store behind the existing App Server lifecycle. It does not decide domain transitions or create a product route.

## Decision
Add forge-core/internal/controlstore as the sole owner of control.db. On Linux excluding Android, the App Server first acquires its existing instance lock, retains the bound os.Root, opens a directory descriptor from that root and gives SQLite the exact /proc/self/fd/<descriptor>/control.db path. The descriptor remains open until SQLite closes, so a configured-path rename or replacement cannot split the cooperating instance lock from the database. The initial database is created descriptor-relative as an effective-user-owned, single-link regular file with exact mode 0600. The closed state layout expands only to control.db and the optional SQLite -journal, -wal and -shm sidecars; every present file is revalidated as private and single-link. Android and non-Linux targets continue to fail before state access.

ADR-0001 is Superseded and decided when to start the Go runtime; ADR-0002 defines a Go-core polyglot stack and explicitly anticipates procured infrastructure. Neither decision permanently prohibits all external Go modules. Replace the over-broad historical zero-require tests with a narrower machine policy: exact reviewed go.mod bytes, an exact go.sum digest, no unapproved external source import, and the sole blank driver import in internal/controlstore/open_linux.go. The forge CLI must continue to build with CGO disabled.

Pin the CGo-free modernc.org/sqlite v1.57.0 driver. Use one pooled connection, immediate write transactions, WAL, FULL synchronous mode, foreign keys, a bounded busy timeout, defensive mode and trusted_schema disabled. Schema v1 has an application identity, exact catalog validation, STRICT tables, explicit indexes, foreign-key checks, quick integrity checks and append-only triggers. Before applying any read-write WAL profile to a nonempty database, inspect its SQLite header and validate its committed main-file-plus-WAL identity, catalog and relational state through a read-only connection. Empty R0-A state initializes v1 transactionally. An exact empty-catalog, single-page, zero-freelist SQLite shell with zero application and user identity in DELETE or WAL mode is the sole recoverable exception because interruption after first-open profile setup but before schema commit can leave that state; initialization retries transactionally on the next start. Foreign, partial, drifted, future or downgraded schemas fail without journal-mode conversion and before listener binding or readiness publication; there is no automatic repair or downgrade.

A Commit accepts one exact canonical Platform Core CommandEnvelope with a non-null expected_version, one to thirty-two exact canonical Go-Control-owned EventEnvelopes, zero to thirty-two bounded outbox messages and a bounded opaque result. It rejects Rust-owned Attempt, Session, Turn and Action aggregate targets. In one immediate transaction it checks exact idempotency-key reuse, globally unique canonical message identities, command and event identifiers, durable causation and correlation, current aggregate version, contiguous aggregate versions, the source component's contiguous EventEnvelope sequence and outbox identifiers. The store independently allocates a contiguous global event range, appends message identities and events, advances the aggregate head, appends outbox rows and stores the exact command bytes plus replayable result. A command cause must already be durable; every Control event must be caused by the current command or an earlier event in that commit, with matching correlation and nondecreasing time. Startup revalidates those causal relations, command range length, and aggregate/source/inbox monotonic order rather than trusting write-time checks. Same key plus byte-identical command returns the original result without appending; same key plus different command bytes rejects. Any insertion or commit failure rolls the complete unit back.

The inbox separately accepts exact canonical non-Control EventEnvelopes under an explicit bounded source-stream identity. The first append permanently binds that stream to one source_component. It appends only the next source sequence, returns exact duplicates as replay, rejects mixed sources or conflicting duplicates and rejects gaps or reorder that do not exactly match durable history. A supplied inbox cause must resolve through the same durable message index with matching correlation and nondecreasing time. Outbox acknowledgement is a separate immutable row. Event, inbox and pending-outbox reads are bounded, ordered and recheck stored payload digests plus canonical metadata before returning bytes.

The App Server opens and validates this store after acquiring the instance lock and before binding or announcing its listener. The existing health wire remains process-level and discloses no storage path, schema, counts or product state. This slice adds no product command/query route, worker, projection, Runtime client, Harness invocation, ID generator, domain state transition, Receipt producer, completion decision, backup command or UI.

## Consequences
The Go control plane now has a crash-consistent private journal foundation that directly consumes canonical Platform Core command and event bytes. Aggregate versions, source-component and global journal sequences, causal message identity, idempotency receipts, outbox work and external inbox cursors survive clean restart and abrupt process exit, and projection or transport slices can build on bounded replay APIs without reading SQLite from clients.

forge-core is no longer a zero-external-module Go module. The SQLite driver and its transitive modules are pinned in go.mod and go.sum and become part of the local App Server supply chain. Exact-manifest and import-containment checks fail on dependency drift; existing non-App-Server Go packages remain independent of controlstore.

An R0-A-only state directory upgrades in place by adding control.db. A server binary that only understands the old exact two-file layout will reject that upgraded directory. Rollback must stop the server and preserve or move the database files as a unit after backup; deleting them would discard product-control history.

The event journal is durable local state, but structural validity and SHA-256 do not authenticate the same-UID operator or make SQLite tamper-proof. The existing lock is a cooperating single-instance boundary, not a hostile local-user fence. WAL durability still depends on the local filesystem and SQLite guarantees.

## Validation
Store tests create and reopen the exact private WAL schema, recover a process exit after WAL profile setup but before the first schema transaction, reject symlink and hard-linked database files, reject foreign/application/version/catalog drift without first converting an incompatible database to WAL, and prove that a renamed configured path still writes only through the retained directory descriptor. They pin all connection pragmas, defensive and immediate-transaction behavior, grouped non-correlated startup query shape, concurrent Close safety, committed-WAL recovery and rollback of an open transaction after abrupt exit. Schema startup failure must happen before readiness publication, and a graceful App Server return preserves a store-close failure.

Transaction tests cover successful append and bounded reads, exact request/result replay across reopen including a non-null empty result blob, stored-request drift rejection, same-key different-command rejection, command/event/outbox conflicts, expected-version races with one winner, aggregate-version mismatch, independent Control source sequences plus store-assigned global order, causal resolution/correlation, Rust-owned aggregate rejection, append-only triggers, outbox acknowledgement and injected outbox failure after event insertion with complete rollback. Corruption/reopen fixtures reject interleaved command ranges, source/aggregate/inbox order reversal, command correlation drift, cross-command Control causes and inbox cause drift. Inbox tests additionally cover independent streams, all three Control-owned source exclusions, mixed-source rejection, exact replay, conflicting duplicate, gap, reorder, injected insertion failure, canonical-byte replay and restart cursor continuity.

Repository validation requires focused and full Go tests, race tests, vet, formatting, cross-target fail-closed builds, architecture and governance gates, fresh-context architecture/security review and formal forge acceptance. No live provider, credential, Runtime process, Harness check, project workspace or external network is used.

## Limitations
Schema v1 is a storage foundation, not the complete control-plane domain. It has no Space, Project, Objective, Change, WorkGraph, WorkItem, Approval, Policy, Attempt projection, Verification join or Outcome repository. It cannot create a user task or execute an Agent.

Outbox rows are not delivered and inbox rows are not produced by a live Runtime transport in this slice. No projection worker consumes either journal, and no cursor is exposed through HTTP, SSE, WebSocket, CLI or TUI. The EventEnvelope Sequence field always belongs to its producing component stream; Commit stores it as the Go-Control source-component sequence while assigning a separate private global_sequence for replay. Inbox stores it under the explicit source stream. Future transport handshakes must bind stream identity and compatibility before ingestion.

Only exact schema v1 is accepted. There is no v0 data migration, v2 migration, online backup, compaction, retention, key rotation, encryption, disk-capacity readiness or corruption repair workflow. The descriptor path requires Linux procfs, and this decision does not broaden R0-A to Android or another operating system.

Proposed status records a candidate and implementation evidence only. It is not an authenticated architecture adoption, ApprovalRecord, authority grant, production-readiness claim or permission for clients to access private tables.

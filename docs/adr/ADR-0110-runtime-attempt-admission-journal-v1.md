# ADR-0110: Runtime Attempt Admission Journal v1

## Context
ADR-0107 and ADR-0109 delivered immutable request and pure lifecycle values, not durable Attempt state. FR-04 must establish Runtime-owned persistence before FR-06 transport can define delivery. Existing Hub v29 stores legacy Run/Group/Graph semantics; it must not become the new Attempt owner by analogy or be migrated incidentally.

The smallest durable step is requested admission. Observed lifecycle transitions require a separate evidence and provenance contract, so they are excluded here. The detailed candidate is docs/design/forge-workspace/runtime-attempt-admission-v1.md.

## Decision
Add an isolated infrastructure sqlite_execution module with SqliteAttemptJournal::from_connection taking ownership of a caller-opened on-disk SQLite main connection. Reject attachments, active transactions, foreign databases, unknown profiles and schema drift. Initialize only an empty database; validate an existing exact version-1 profile without repair or migration. Require WAL, synchronous FULL, foreign keys and bounded lock waits. File selection, permissions, descriptor safety, VFS and library trust remain the explicit caller responsibility, not a security guarantee of this adapter.

A private versioned compact canonical storage record captures all fifteen frozen AttemptRequest input fields through getters, with explicit nulls, normalized sets, exact decode/re-encode equality and a domain-separated SHA-256. Restoration reconstructs AttemptRequestInput and invokes the frozen validator. Neither existing request nor lifecycle source or API changes. The new adapter does not consume the lifecycle value. A pure public request_sha256 preparation helper lets callers bind creation payloads without duplicating the private codec; it opens no storage and reserves no identity.

Reuse Platform Core canonical EventEnvelope and digest, then enforce the narrower creation profile: Runtime source, exact Attempt/scope/snapshot, aggregate version and sequence 1, forge.runtime.attempt_requested schema version 1, no causation/extensions/payload Artifact, and exactly request_sha256 plus requested state in the inline payload. Caller-supplied identity, actor, correlation and occurrence time remain unauthenticated declarations.

Within one immediate transaction, validate the complete bounded journal, reserve database-global Attempt and idempotency identities, assign the next contiguous store-local cursor, and commit immutable request, creation event and retained pending outbox together. Exact same-key request and event bytes return the original result without new rows; every difference conflicts. Replay precedes capacity rejection. Every read and write revalidates schema, canonical bytes, digests, redundant identity and one-to-one relational completeness in its transaction snapshot.

Limit admissions to 1024, each request to 64 KiB, each event to 16 KiB and total request/event bytes to 32 MiB. Pending pages accept 1 through 64 items and at most 256 KiB event bytes; cursor zero starts reading and cursors beyond the snapshot head are rejected. Cursors are store-local, not transport or cross-store identifiers. Storage Invalid, Conflict, Capacity, Corrupt and Unavailable outcomes never synthesize an effect uncertainty transition. A commit response loss is resolved only by explicit exact replay after reopening.

## Consequences
This is a real SQLite admission foundation, closing only FR-04a. Requested remains non-runnable and does not authorize an effect. Event, request and outbox survive reopen as one atomic fact set; no sender, ack or deletion API is added. Full-journal validation is bounded but is not a constant-work or unlimited-retention design.

The source proof evolves through exact path and whole-source-digest consumer entries after existing Serde, macro and path checks. No directory-wide exception or lifecycle consumer is allowed, and reviewed source reuse via path attributes is rejected. Frozen request/lifecycle and Platform Core sources, dependency manifests and legacy Hub schema remain unchanged.

## Validation
Exercise strict complete request round trips, nested missing/duplicate/unknown field and noncanonical mutations, normalization, invalid restored references and bounds, and creation-event binding substitutions. Exercise exact replay, event-metadata conflicts, Attempt/key/event/message uniqueness, contiguous cursors, bounded pending pages and capacity, reopen, concurrent writers, schema and relational corruption, missing event/outbox, and rollback on injected precommit failures.

Use isolated test-owned files and subprocess interruption to distinguish uncommitted work from committed admission whose response was lost. Review the design and final code in fresh contexts, verify frozen-source and new-consumer boundaries, run Rust formatting, strict Clippy, tests/build, architecture/governance and same-tree formal repository acceptance before retaining R0-C7 completion markers. No real provider or model call is authorized.

## Limitations
This adapter does not open production filesystem paths, secure directories or descriptors, migrate Hub databases, authenticate actors or evidence, create a CommandEnvelope or StartAttempt wire, consume Go Control, resolve grants or artifacts, reserve budget, dispatch tools or models, advance lifecycle, own Session/Turn/Action, deliver or acknowledge outbox, produce ExecutionReceipt, decide completion, or add application/protocol/CLI/UI consumers. FR-04 later lifecycle/recovery integration, FR-06 and FC-07 remain open.

Same-user external mutation or full database rollback, malicious SQLite/VFS or hardware, trusted source replacement and cross-store cursor identity are outside this profile. Valid records prove only stored structural and relational consistency, not observation truth, effective authorization or tamper-resistant history. ADR-0110 remains Proposed with null acceptance metadata; engineering acceptance cannot promote its lifecycle or grant authority.

# ADR-0084: Authenticated Architecture Decision Lifecycle Authority Service v1

## Context
ADR-0081 establishes a real internal approval authority relative to explicit external root, epoch, trusted observation and revocation high-water inputs. A successful fresh authorization is represented by an opaque `StoredAuthorization` created only after the exact signed approval ledger is durably published and authenticated on reopen. Its detached prerequisite source and a generic verified bundle are data views, not transferable mutation capabilities.

ADR-0082 freezes exact lifecycle v1 structures for an immutable Proposed source, an approval prerequisite, a signed transition request, acceptance and supersession receipts, an append-only ledger, a materialized view, one enclosing signed state image and an unsigned delivery result. Its Python core and Go parity package are structural oracles. They deliberately perform no external trust decision, Ed25519 verification, currentness decision, state signing, CAS publication or capability handoff.

The missing narrow slice is an in-process lifecycle authority. A fresh transition must join those boundaries without broadening either one: it must consume the real `StoredAuthorization`, prove that the request contains the exact prerequisite and proposal bytes derived from that same authorization and trusted observation, authenticate independently rooted lifecycle authority, publish one atomic state update outside the repository and never rewrite the source ADR. Historical retrieval must remain available after approval expiry or later upstream revocation without creating a new lifecycle effect.

## Decision
Propose the isolated stdlib-only Go package `authenticatedadrlifecycleauthority`. Its fresh API accepts protected-path configuration, one exact canonical encoded transition request, a real pointer to `approvalauthority.StoredAuthorization` and explicit external approval and lifecycle root pins, epochs and observation time. It does not accept `VerifiedBundle`, `AcceptancePrerequisiteSource`, raw approval receipts, generic projections or caller-declared stored labels as mutation authority.

Before any signing or publication, the service decodes the exact protected signature profile and both roots, compares them to external pins and explicitly requires approval and lifecycle trust domains, principal domains, usages, key identifiers, Ed25519 public keys and principal identities to be disjoint. Fixture authority identifiers are rejected. The lifecycle request signature is verified under its exact v1 usage and domain. The service obtains a detached source only by invoking `AcceptancePrerequisite` on the opaque value, requires the same approval root, epoch and trusted observation, requires exact profile and approval-root bytes, reconstructs every prerequisite field and compares its canonical bytes, and compares the exact proposal document and binding to the strict Proposed ADR source. Generic verification cannot drive this path.

Exact replay is checked under the lock before current capability projection, capacity or fresh currentness. If the idempotency key and complete canonical stored request match, `TransitionAndStore` returns an opaque exact-replay result and makes no lifecycle state change. A reused key with different request bytes fails. Otherwise the service requires a current authorized capability, exact current request time, the next sequence, prior ledger digest and current head-set digest, and between zero and sixty-four sorted supersession targets equal to the immutable source `supersedes` list. Each target must be an exact current Accepted decision. The new Proposed decision is accepted and all targets are superseded in one new entry, ledger, view and enclosing state; source bytes are never changed.

The service first builds a proof-shaped prospective full bundle and passes it through the frozen Go lifecycle decoder before reading the signing seed. It then loads an exact protected thirty-two-byte seed whose public key matches the independent lifecycle state-sign usage, signs the acceptance receipt, each supersession receipt and state under their frozen distinct domains, and validates the complete bundle and every Ed25519 signature before commit. The only recognized and published lifecycle content is the canonical repository-external `architecture-decision-lifecycle-state.v1.json`, containing the complete ledger and materialized view under one state digest and signature.

State operations bind exact authority, repository, state-directory, lock, seed, root and state identities. Authority and state directories are effective-UID-owned mode `0700`; protected leaves are effective-UID-owned regular mode `0600` with link count one. The lock is an explicitly provisioned protected leaf that the authority never creates or repairs. Symlinked ancestry or leaves, aliases, special files, overlapping roots, traversal, replacement and time-of-check/time-of-use drift fail closed. A fresh operation takes a nonblocking exclusive lock, authenticates the current state, enforces CAS, writes an exclusive same-directory temporary file, completes and synchronizes it, closes and rereads exact bytes, rechecks CAS and bindings, atomically renames, synchronizes the directory, reopens exact bytes and revalidates the state and all signatures. Pre-rename failures return no result; post-rename ambiguity is persistence uncertain and also returns no result.

`ReplayStored` is a separate historical read operation. It authenticates the exact externally pinned roots, signed current lifecycle state and signed historical request but deliberately does not reevaluate the originating approval or request validity window, read a seed, sign or publish. It requires the lifecycle lock leaf already to exist, acquires it without creating or synchronizing application metadata and fails closed when it is absent. Therefore an exact stored transition remains retrievable after upstream approval expiry or revocation while a missing or different historical request produces no effect. Ordinary filesystem reads may retain host-managed access-time semantics and are not claimed absent.

The opaque `StoredTransition` is privately sealed and returned only after fresh strict authenticated reopen or exact locked historical replay; all exposed bytes are detached. Its unsigned delivery disposition does not create authority. The service hard-excludes ADR-0079 through ADR-0084 plus configured proposal-binding hashes from self-bootstrap. It caps the state at two hundred fifty-six entries and decisions, each request at sixty-four targets and every artifact at its exact v1 byte ceiling. It supports Unix hosts with open-file-description `flock` semantics in this slice; AIX, Solaris and non-Unix hosts fail closed as unsupported.

## Consequences
A trusted in-process caller can atomically advance the frozen lifecycle ledger from one real stored approval capability without granting repository-write or transport authority. One operation can accept a new exact Proposed source and supersede multiple current heads without exposing a partial view. Exact replay is independent of later approval currentness and does not extend or recreate the originating authorization.

The state image is self-authenticating relative to explicit external pins and contains its complete history and current materialized view. CAS, file identity, synchronization and strict reopen provide crash-conscious local durability evidence. They do not provide an external monotonic checkpoint or prevent a sufficiently privileged actor from restoring an older valid image.

The implementation remains an internal Proposed authority surface. It adds no repository artifact, source mutation, status rewrite, acceptance frontmatter, command, route, socket, registry entry, scaffold distribution, production root, key provisioning, Grant, policy-enforcement point, permission, generalized Effect artifact, compliance claim or G0 closure.

## Validation
Generate fresh independent approval and lifecycle Ed25519 roots in tests and obtain every fresh prerequisite from the real approval authority `AuthorizeAndStore` result. Mutate root pins, epochs, root content under an unchanged digest, trust and principal domains, usages, key identifiers, public keys, signature bytes and domains. Require every approval-to-lifecycle authority reuse and every fixture identifier to fail before signing or publication. Mutate every prerequisite field, proposal byte, observation, request time, expected sequence, ledger and head digest, target relation and idempotency branch.

Exercise one-target-free acceptance and an atomic two-target supersession join. Require exact current targets, immutable source parity, time non-regression, capacity failure at two hundred fifty-six entries or decisions and sixty-five targets, and hard bootstrap exclusions. Require zero, forged, detached or generic authorization-shaped values to fail a fresh transition, while exact replay precedes current capability and capacity checks.

Race identical operations and require at most one append. Attack absolute and relative path grammar, symlink ancestry and leaves, directory and leaf modes, owner, link count, special types, aliases, root overlap, binding replacement and same-image stale CAS. Inject random, exclusive-create, write, file-sync, close, pre-rename, cleanup-remove, rename, directory-sync, reopen and session-close failures and require no opaque output. Require correct failed versus uncertain classification. Remove the replay lock from both empty and valid-state layouts and prove that historical replay makes no authority application write and leaves directory entries, mode and modification time unchanged.

Run focused tests, the race detector, vet, formatting and frozen lifecycle and approval contract tests. Cross-compile the unsupported AIX and Solaris boundary. Run strict ADR v2 validation, the architecture checker, export, file, line and function caps, mode `0644`, link count one, cache absence, diff hygiene and an independent security and semantic review before recording physical pins. Do not describe this Proposed slice as stable production provisioning or architecture compliance.

## Limitations
ADR-0084 remains Proposed. It provisions no production signature profile, root, key, seed, state directory, HSM, process-isolated signer, trusted clock, approval revocation publisher, authenticated caller, command, socket, route, registry or remote transport. Effective-UID ownership, mode and link checks plus best-effort seed clearing are hygiene evidence, not proof of private-key isolation or secure erasure.

The local lock, CAS, atomic rename, synchronization and authenticated reopen protocol does not prevent same-UID or privileged rollback to an older valid signed image. It contains no external high-water checkpoint, hardware monotonic counter, cross-host consensus, backup protocol, key rotation or root-epoch migration. Failure after rename remains intentionally uncertain, and an operator must reconcile the exact signed state before retrying a different request. A failed best-effort cleanup may leave a dot-prefixed unpublished temporary image; it is never opened as lifecycle state or returned as output and requires bounded operational cleanup.

Historical replay proves that an exact transition exists in the currently authenticated lifecycle image. It intentionally does not prove that its originating approval remains current, undo a later lifecycle state, or authorize a new transition. Existing-lock-only replay cannot bootstrap an empty state directory. The unsigned delivery envelope is not an independently signed artifact.

The v1 state has no compaction or rollover and fails closed at its fixed entry, decision, target and byte ceilings. The service does not reject an already stored lifecycle effect merely because an upstream approval later expires or is revoked; defining reversal requires a new versioned lifecycle transition. It does not generate or rewrite an Accepted ADR source, publish immutable derived repository artifacts, enforce supersession in a repository transaction, make an architecture-fitness or compliance judgment, provide Grant, permission, generalized Effect artifact or policy-enforcement authority, or close G0.

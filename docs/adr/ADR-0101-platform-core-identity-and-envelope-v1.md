# ADR-0101: Platform Core Identity and Envelope v1

## Context
The App Server bootstrap establishes a local product process but intentionally has no product command, event, artifact, or aggregate semantics. The next product slices need one language-neutral boundary before Go control state, Rust execution state, Harness verification, HTTP transport, or SQLite projections can safely refer to the same work. Existing governance and Kernel operational contracts are valuable structural evidence, but their IDs, attestations, task bindings, and authority-neutral closure semantics are specialized and cannot be renamed into the product protocol without coupling unrelated histories.

Defining every Objective-to-Outcome object at once would combine identity, dispatch, execution, verification, persistence, and completion authority. The first Platform Core increment instead needs a narrow contract that later receipts and state machines can build upon without changing the meaning of its envelope. It must support bounded inline payloads and immutable artifact references while making clear that structural validity is not authentication, authorization, durable append, content provenance, or state transition.

## Decision
Adopt Platform Core Envelope v1 as a pure cross-language contract covering typed opaque IDs, `EntityRef`, `ActorRef`, `RecordRef`, contiguous `ScopeRef`, `ArtifactRef`, `CommandEnvelope`, and durable-shaped `EventEnvelope`. Keep the canonical schema, protocol note, and golden under `docs/contracts`; expose independent Go and Rust bindings in their existing domain trees and a dependency-free Python Harness conformance implementation. Do not create a fourth service, generated shared runtime library, database, network endpoint, Registry capability, or scaffold distribution in this slice.

Platform IDs use a frozen three-letter type prefix plus a 26-character lowercase Crockford-base32 suffix whose first character is zero through seven. The prefix rejects type confusion but the suffix remains opaque: no consumer may infer a path, provider, database row, timestamp, locality, or authority. Space through WorkItem IDs are created by the Go control plane; Attempt through Action and Artifact logical IDs are created by the Rust execution plane; Verification IDs are created by Harness; actor identity remains owned by a future identity boundary. CAS owns publication and storage of `content_id` bytes, not the `art_` logical identity. External and legacy IDs stay explicit references rather than being accepted as Platform IDs. This generic envelope does not interpret `schema_name` as a StartAttempt payload contract or enforce entity creation/first-event semantics; those require a separately reviewed payload/state contract and durable consumer.

Command and Event envelopes carry exact canonicalization and envelope version, an independently versioned payload-schema name/version pair, specialized and common message identity, actor, scope, correlation, direct causation, exactly one bounded inline payload or ArtifactRef, and namespaced non-authoritative extensions. Command adds target, issue/deadline time, idempotency key, nullable expected version, and nullable authorization reference. Event adds aggregate, aggregate version, component sequence, source component, occurrence time, and nullable source ProjectSnapshot. The common and specialized IDs share one suffix to prevent two independent identities for one wire message. A non-null direct cause cannot equal the current message; durable consumers still resolve cause order and correlation. Target and aggregate refs must occur in scope; event snapshot refs must match scoped ProjectSnapshot.

ArtifactRef binds a logical ID, exact SHA-256 content identity, declared size, kind, media type, producing Attempt, source ProjectSnapshot, provenance RecordRef, creation time, retention, and sensitivity. It carries no path. An artifact-backed envelope must bind that source ProjectSnapshot and producing Attempt to the same scope, and the artifact cannot postdate command issue or event occurrence; foreign-scope artifacts need a future explicit source-scope contract. Callers possessing content must independently recompute digest and size; pure contract validation cannot prove existence or provenance. Inline payloads are capped at 32 KiB, extensions at 16 entries and 8 KiB, complete envelopes at 256 KiB, ArtifactRef at 16 KiB, depth at twelve, arrays at 256, object fields at 64, and strings at 16 KiB. Depth starts at one for the complete root; every object member value or array item adds one, keys add none, and scalar leaves occupy their current depth. Payload and extensions are first checked as depth-one component roots, after which the complete envelope is checked again from its root. Programmatic writers apply an aggregate occurrence budget and stop while writing the first byte beyond the applicable ceiling; Go also rejects ambiguous typed-nil maps and slices. Python serializes a caller-owned graph once, validates a detached decode of those exact bytes, and returns or digests the same bytes so alias mutation cannot create a wire image its decoder rejects. Duplicate keys, floats, unknown contract fields, malformed UTF-8, forbidden controls or bidi formatting, noncanonical bytes, invalid typed ancestry, and future envelope versions fail closed.

Canonical observation digests are SHA-256 over a NUL-terminated type domain plus exact compact canonical bytes. They exist only for cross-language parity and are not signatures or wire identities. Payload semantics remain owned by the schema named in each envelope and must be validated separately by its consumer. Envelope validity cannot authenticate actor or referenced records, authorize or execute a command, enforce idempotency or expected version, append or order an event, persist bytes, resolve content, advance state, or attest completion.

## Consequences
Go control, Rust runtime, and Harness can now exchange and independently reject the same identity, scope, payload, event, and artifact-reference bytes. Later ExecutionReceipt, VerificationReceipt, Runtime journal, control inbox, and App Server APIs can reuse this vocabulary instead of inventing transport-specific IDs. Large semantic bodies have a defined ArtifactRef escape hatch before any CAS implementation is selected.

The contract is intentionally verbose because nullable ancestry is explicit and unknown top-level fields fail closed. Adding an envelope field requires a reviewed new version rather than relying on silent language defaults. The current schema is a structural shadow; executable validators remain load-bearing for canonical bytes, duplicate detection, size ceilings, ID/type relations, ancestry, payload choice, identity suffix equality, deadline ordering, scope membership, and snapshot matching.

This slice does not complete Platform Core v1. ExecutionReceipt, VerificationRequest/Receipt, WorkItem/Attempt/Action state and payload vocabularies, stable cross-language rejection codes, sequence journals, idempotency storage, CAS publication, App Server command/query routes, Runtime transport, and a real Objective-to-Outcome vertical flow remain separate roadmap increments.

## Validation
Pin one golden containing an inline WorkItem-targeted command declaration, an ArtifactRef-backed runtime event declaration, and their shared supplied product ancestry. The fixture illustrates opaque IDs and does not prove payload-specific StartAttempt semantics, entity creation, or first introduction. Go, Rust, and Python must decode exact canonical bytes and reproduce the same domain-separated SHA-256 values. Each implementation must reject unknown and duplicate fields at every depth, booleans in integer fields, floats and signed-integer overflow, invalid UTF-8, forbidden Unicode, whitespace and trailing framing, malformed IDs and namespace/type mismatches, noncontiguous scope through Action, mismatched message suffixes, self-causation, target or aggregate outside scope, deadline inversion, payload ambiguity, command/event artifact scope, producer and time drift, bad media types and content identity, ambiguous Go typed-nil containers, high-fanout output beyond aggregate/byte budgets, oversized payload/extension/document, and event snapshot drift. The Python checker additionally rejects mutable decoder input, validates the exact detached byte snapshot emitted from mutable programmatic input, and in explicit file mode rejects paths above 4096 filesystem bytes or 64 components before any descriptor open, closes partial descriptor acquisition on metadata failure, requires Linux `O_PATH` and procfd support, rejects special, linked, multilink, or oversized metadata before any readable leaf open, and detects leaf or ancestor replacement and rewrite during bounded reads.

Run focused Go, Rust, and Python suites; Go race and vet; Rust formatting and strict Clippy; JSON Schema shadow validation where the dependency is available; ADR v2 validation; repository architecture, governance, gate, and full acceptance. Require fresh-context architecture and security review before marking the roadmap slice done. No model, provider, credential, external network, process execution, state database, or product mutation is needed by these tests.

## Limitations
The typed suffix grammar establishes no collision service or generator in this slice; producers still need a separately tested cryptographic or monotonic 128-bit generator before live creation. Actor type is caller-declared and unauthenticated. RecordRef digests are not resolved. Artifact content, size, media type, provenance, retention, and sensitivity are declarations until a future CAS and policy boundary verifies or enforces them. Payload schema support is also a consumer decision even when the envelope and positive schema version are structurally valid. Current rejection messages are diagnostics, not stable machine error codes; the remaining PC-06–08 conformance work must define that taxonomy and its shared malformed corpus before product callers branch on errors.

Event shape is durable-ready but this pure implementation does not append, deduplicate, sequence, replay, migrate, or project events. Command shape does not reserve an idempotency key, check current aggregate version, evaluate policy, consume Approval or Grant, or dispatch Runtime work. Extensions are accepted only as bounded namespaced data and never carry authority. Schema-name validity does not prove that its payload schema exists or passed semantic validation.

ADR-0101 remains Proposed. Structural parity and repository acceptance provide implementation evidence for this narrow contract candidate only; they are not an authenticated ADR lifecycle transition, product readiness claim, completion receipt, authorization, persistence guarantee, or permission to add effectful App Server routes.

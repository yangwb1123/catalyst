# ADR-0107: Runtime Attempt Request Domain v1

## Context
ADR-0101 and ADR-0102 provide the Rust domain crate with pure Platform Core identity, reference, Artifact, executor, idempotency and Attempt-state vocabulary. ADR-0106 can select one passive WorkItem candidate in Go, but deliberately does not create or dispatch an Attempt. The Runtime still lacks one owned value that states exactly what a future durable Attempt creation request must bind.

The broader FR-03 task also includes Attempt lifecycle, Session, Turn and Action. FR-04 owns execution persistence and outbox, FR-06 owns the local protocol, and FC-07 depends on that protocol. Implementing a StartAttempt wire or RuntimePort now would let transport fixtures define current state before Runtime has a durable aggregate owner. Implementing all of FR-03 in one slice would freeze several independent lifecycles and effect boundaries without their persistence and recovery evidence.

Existing Run, Group, Graph and scheduled-node contracts bind different legacy product identities, protocol histories and dispatch semantics. Treating one as the new Attempt domain would make compatibility state the accidental Runtime product authority and would preserve the scheduling ownership overlap that the Forge Workspace plan is intended to remove.

## Decision
Add one pure FR-03a module to the Rust domain crate. `AttemptRequest::try_from(&AttemptRequestInput)` validates caller-supplied values and defensively clones them into a private-field owned value exposed only through read-only getters. Subsequent mutation of the input or its strings, vectors, references, descriptor and budget cannot change the constructed request.

Require a complete contiguous Platform Core Scope from Space through Attempt, with Session, Turn and Action absent. Require explicit Attempt, WorkItem, Project and ProjectSnapshot entity references whose exact types and identifiers match the corresponding scope fields. Bind positive bounded Objective, Change, WorkGraph and WorkItem versions in one `ControlVersionBinding`; these remain caller declarations and are not current-state observations.

Validate one caller-declared `ExecutorDescriptor`; an optional context Artifact whose source snapshot equals the request ProjectSnapshot and whose producer is not the requested, not-yet-created Attempt; an optional `forge.runtime.workspace_capability` RecordRef; an optional `forge.control.capability_grant` RecordRef; and a bounded set of `forge.control.approval_record` RecordRefs. Approval references and requested effects are set-like: reject duplicates and normalize accepted values into deterministic byte order. Requested effects are bounded lowercase tokens; an effect-free request may omit the Grant, while any non-empty effect set requires a declared Grant. No reference is resolved or authenticated.

Bind a bounded `AttemptBudget` covering duration, cost, model calls, tool calls, input tokens, output tokens, output bytes and network bytes. Timeout must be positive, bounded and no greater than the duration budget. Reuse the Platform Core 16-to-128-byte visible-ASCII idempotency-key validation. Derive the initial state as exactly Platform Core `requested`; the caller cannot supply a state.

Add no reducer or transition method, Session, Turn, Action, serde derive, canonical wire, digest, schema, ID or time generation, database, journal, outbox, CAS, Artifact resolution, protocol, adapter, authority lookup, budget reservation, Reconciler consumer, dispatch, provider, tool, filesystem, process, network, verification, completion or user entry point.

## Consequences
Runtime gains one bounded owner for the immutable input to a future Attempt aggregate. Cross-scope substitution, out-of-range named Control-version declarations, self-produced or snapshot-mismatched context Artifacts, wrong record types, contradictory timeout and budget declarations, duplicate set members and mutable-input aliasing become independently testable before any I/O exists.

Equivalent Approval and effect permutations produce one normalized owned value, but equality and structural validity do not prove that any referenced record exists, is current, is authorized or permits an effect. The `requested` state records construction only; it does not mean accepted, persisted, claimed, dispatched or running.

This slice intentionally leaves FR-03 incomplete. The dependency chain remains FR-03a request value, then the remaining FR-03 lifecycle values, FR-04 execution journal and outbox, FR-06 local protocol, and finally FC-07 RuntimePort. Each boundary requires a separate reviewed decision and acceptance evidence.

## Validation
Table and boundary tests must cover a valid effect-free request and a valid effect-bearing request, every exact entity and record type, full and incomplete Scope shapes, explicit-reference substitution, context snapshot mismatch and self-producer rejection, minimum and maximum Control versions, every budget and timeout boundary, malformed idempotency keys, invalid effect tokens, empty and maximum sets, duplicate Approval/effect members, non-empty effects without a Grant, and all stable validation-error families.

Ownership and determinism tests must mutate representative values from every caller-owned field class after construction, compare repeated construction, permute set-like inputs, and confirm normalized getters expose no mutable alias. The state getter must always return `requested`, and source-boundary tests must reject reducer, serde/wire, persistence, application, infrastructure, interface, Hub, provider, tool, filesystem, process, clock, random and network dependencies.

Rust domain and workspace tests, all-target build, formatting, strict Clippy, architecture and governance checks, fresh architecture/domain and security/reliability reviews, the strict ADR v2 validators and formal repository acceptance must all pass before R0-C5 is marked complete. Passing only demonstrates bounded pure construction, relationship validation and ownership on the reviewed source tree.

## Limitations
All input is caller supplied. Validation does not authenticate the caller, executor, Artifact producer, workspace capability, Grant issuer, approver or principal; resolve RecordRefs or Artifact bytes; verify digests; observe current Control versions; prove Scope lineage; check expiry, revocation, remaining budget or permission; or reserve any resource.

The request has no canonical bytes or stable cross-process/source compatibility promise. Its idempotency key is only a structurally valid value: there is no durable key reservation, same-key payload comparison, replay acknowledgement or no-resend transaction. The request is neither a CommandEnvelope payload nor a StartAttempt command.

There is no Attempt aggregate, lifecycle reducer, state-transition authority, Session, Turn, Action, RuntimeEvent, ExecutionReceipt, persistence, crash recovery, protocol handshake, Go consumer, Reconciler effect, WorkItem transition, Harness verification or completion join. Completing R0-C5 closes only the FR-03a pure request subset, not FR-03, FR-04, FR-06, FC-07, F2, F3, F4, F6, R0 Developer Preview, Objective-to-Outcome or the full Forge Workspace application.

# ADR-0085: Authenticated ADR Lifecycle Authority Evidence and Source-only Governance Distribution

## Context
ADR-0084 freezes independently reviewed Catalyst-repository-only Go evidence for a narrow authenticated ADR lifecycle authority. A fresh transition consumes the real opaque `StoredAuthorization` from ADR-0081, authenticates independent lifecycle trust, validates the frozen ADR-0082 request and relations, signs receipts and one state image, and publishes a repository-external state update by locked durable CAS. Exact historical replay does not reevaluate upstream approval currentness and makes no lifecycle authority application write.

That implementation remains Proposed and internal. It provisions no production root, key, seed, state directory, clock, revocation publisher, authenticated caller, command, socket, route or transport. It does not rewrite ADR source, publish an Accepted document, grant permission, implement a generalized Effect, enforce architecture compliance or close G0.

Registry v34 already distributes the ADR-0082 Python structural core and its lifecycle governance as an exact source-only closure. The next governance version must record ADR-0084 honestly while preserving that distribution boundary. Generated projects need the authority decision and governance evidence, not the authority implementation.

## Decision
Adopt Registry v35 with a separate `authenticated_adr_lifecycle_v1_go_authority_evidence` block whose semantic authority is ADR-0084 only. The block records the frozen Go contract and authority paths, exact structural parity, real opaque `StoredAuthorization` requirement, independent approval and lifecycle trust facts, request and state signature handling, atomic multi-target acceptance and supersession, durable CAS publication, exact idempotent replay and existing-lock-only historical replay.

The same block states the complete negative boundary. No production trust input is provisioned. Governance and scaffold must not copy either Go package, any root, key, seed, state, receipt or ledger, and must add no command, socket, route, service, evaluator, producer, Skill, runtime profile, repository mutation or generalized effect. Catalyst repository evidence is not generated-project capability.

Preserve the complete Registry scope mapping and its canonical SHA-256 `8ba82b638e8031f0d1be2b9ea6d522a4b9cf064a4ed532e1f0d3281f2dfe874c`. Retain exactly one non-load-bearing `governance.authenticated_adr_lifecycle_v1_candidate` checker-only shadow for the source-distributed Python structural candidate. Add no Go detector and no authority service detector.

After the shared Registry and governance checks pass independent review, source-distribute exactly four new files: ADR-0084, ADR-0085, the v35 lifecycle-authority governance module and its test. Existing source fragments continue to own every prerequisite, including the ADR-0082 structural core and the v34 lifecycle exact24 closure. The v35 fragment must not duplicate those paths or expand to Go.

The generated governance test runs Registry, ADR, activation, discipline, route, detector and negative-boundary assertions without `forge-core`. Only the Catalyst-only Go implementation closure and semantic recomputation test is skipped when that directory is absent. Source Catalyst runs recompute the exact forty-four-file aggregate and semantic markers from current bytes.

## Consequences
The shared policy can state that a real narrow lifecycle authority exists in Catalyst without claiming it is installed, routed, provisioned or shipped. Its physical decision pin and exact authority-package aggregate make the evidence auditable, while semantic marker checks keep the aggregate tied to the declared surface.

Generated projects receive enough source to validate the governance claim and its distribution exclusions. They receive no authority implementation and cannot manufacture a `StoredAuthorization`, sign lifecycle state, publish a transition or replay protected state.

The protected policy hash, exact source inventories and legacy migration tests make any later promotion or distribution expansion explicit. Checker success and `forge accept` remain evidence only, not ADR acceptance or lifecycle authority.

## Validation
Validate ADR-0084 and ADR-0085 as strict Proposed ADR v2 documents and pin their physical, body and self digests. On Catalyst, enumerate exactly forty-four direct Go files with no symlink, directory, special or cache entry; require regular mode `0644`, link count one and the frozen aggregate SHA-256. Recheck the opaque authorization handoff, independent roots, signature domains, atomic acceptance and supersession, durable publication and historical replay markers.

Mutation-test Registry v35 version, full scope mapping and hash, the authority evidence block, both new canonical references, physical and aggregate pins, both Catalyst-only reference implementations and the non-capability declaration. Promote any boundary boolean, reclassify either Go implementation as distributed or insert a candidate or authority token into scope, routes or detectors and require failure.

Run the new governance suite directly in Catalyst and in a temporary tree without `forge-core`. Require only the implementation audit to skip in the generated shape. Run the old lifecycle governance suite directly and through recursive governance acceptance so active Registry migration cannot silently disable it.

After shared review, validate the exact4 scaffold through fresh generation and a real v34-like legacy projection. Require fixed source and target SHA-256, mode `0644`, link count one, no-follow reads, exact closure, ledger ownership and byte parity. Mutate missing, extra, symlinked, hard-linked, mode-drifted and forbidden authority or runtime artifacts and require failure.

## Limitations
ADR-0085 remains Proposed. It neither accepts ADR-0084 nor promotes the authority to production. It supplies no root, key, seed, state, caller identity, trusted clock, revocation publisher, deployment, HSM, process isolation, command, socket, route, service, remote transport, operational recovery or external rollback-resistant checkpoint.

The recorded authority is bounded by ADR-0084. It can publish only its repository-external lifecycle state and does not generate immutable Accepted repository artifacts, enforce repository supersession, provide architecture compliance, issue a Grant, attest permission, create a generalized Effect artifact or close G0.

The source-only four-file distribution is governance evidence. Generated trees deliberately cannot recompute the absent Go package aggregate and cannot exercise its authority. Any proposal to copy Go, provision trust, activate runtime wiring or change the exact source closure requires a new versioned decision and independent review.

# ADR-0093: Decision Capsule Structural Replay Governance and Source Distribution

## Context
ADR-0092 freezes a four-object structural replay DAG over one exact ADR-0090 decision closure: a complete ordered `StructuralReplayManifest`, an embedding `DecisionCapsule`, a separately sealed compare-only `EvaluationBranch`, and an outer `StructuralReplayClosure` that alone owns the dedicated unresolved ReflectionReport attachment array. Upstream ArtifactRefs remain opaque and uninterpreted. Its Python, Go, and Rust implementations reproduce the same physical golden and object seals, but the core is intentionally isolated and Proposed.

The dependency-free Python implementation can be copied into generated projects. The Go and Rust implementations are independent Catalyst-repository parity evidence; distributing either would imply a toolchain and runtime ownership boundary that this decision does not provide. The shared Rust `lib.rs` also contains unrelated registrations and therefore cannot be whole-file pinned.

The checker has an honest pinned-golden mode. Registry wiring can execute exactly `python3 harness/decision_capsule_contract_check.py --golden .` without inventing stdin, an arbitrary request, a runtime consumer, or a check-to-use handoff. Governance must preserve the distinction between a reproducible structural contract and a complete DecisionCapsule, replay engine, Reflection runtime, PDP, or controller.

## Decision
Propose Registry v39 with one `decision_capsule_structural_replay_core_v1_candidate_contract` block. Preserve every Registry scope array and the canonical scope SHA-256. Do not add `StructuralReplayManifest`, `DecisionCapsule`, `EvaluationBranch`, `StructuralReplayClosure`, or any contained record to shipped or planned kinds, evaluators, producers, projectors, adapters, services, or runtime profiles.

Register exactly one non-load-bearing shadow detector. Its argv is exactly `python3 harness/decision_capsule_contract_check.py --golden .`, cwd is `repo_root`, shell mode is false, and invocation ownership remains with the operator. The detector validates only the byte-pinned golden. The standalone explicit-file checker mode does not create a Registry data plane, request route, or runtime integration.

Source distribution is exactly nineteen files: ADR-0092, its Schema and golden, the exact nine-file Python package, checker, three focused root tests, this decision, and its governance module and test. Generated projects receive none of `forge-core/internal/decisioncapsulecontract`, `forge-runtime/crates/domain/src/decision_capsule_contract`, the shared Rust registration, a runtime binary, Skill, route, service, database, journal, external-history resolver, model or rule evaluator, effect executor, state, key, Grant, Approval, PDP, controller, or Reflection runtime. The candidate freezes the complete context-route include projection and independently inventories both `.agent/skills` and portable `skills` roots for candidate identifiers and canonical contract references, so an alternate-named Skill or routed distributed core file fails closed.

Registry evidence pins the ADR-0092 physical document, Schema, golden, four semantic object seals, the exact thirteen-file Python aggregate, exact sixteen-file portable core, Catalyst-only exact fifteen-file Go aggregate, and Catalyst-only exact fourteen-file Rust module aggregate. The Rust aggregate includes its focused nested tests. Governance does not pin all of `domain/src/lib.rs`; it requires a regular `0644`, single-link file containing exactly one `pub mod decision_capsule_contract;` line. Catalyst-only parity and roadmap requirements are selected by explicit `repository_flavor: catalyst_source`; scaffold projects use `repository_flavor: scaffolded_project` plus their ownership ledger, never an ambient documentation-file sentinel.

All thirty-two replay attestations remain false, both replay controls remain false, and the only branch comparison result remains exact structural reference equality. Candidate metadata sets all seven completion claims false, including the narrowly named structural-replay repository slice. The implementation-roadmap item remains unchecked until independent review and formal `forge accept`; ADR-0092 and ADR-0093 remain Proposed before and after any repository-slice promotion. ADR-0038 remains ADOPTED-PARTIAL, while complete DecisionCapsule semantics, AuthorizedTransactionSpec, authenticated PDP, authority promotion, controller behavior, runtime replay, persistence, and Reflection remain open.

## Consequences
Generated projects can reproduce the same pure Decision Capsule structural replay closure using dependency-free Python and the exact pinned fixture. Catalyst retains Go and Rust parity as independent repository evidence without exporting either implementation or the shared registration.

Registry v39 adds no authority or execution surface. A valid result proves only exact supplied-byte validation, upstream reseal, full manifest projection, deterministic reference comparison, and outer placement of the dedicated unresolved reflection attachment. It does not interpret upstream ArtifactRef kinds or establish attempt-history completeness outside the supplied ADR-0090 closure, external history, source or result authenticity, evaluator independence, replay equivalence, model or rule evaluation, world state, authorization, append, persistence, execution, outcome, completion, or effect.

Candidate governance remains pending. Formal acceptance may later close only the narrowly named structural-replay repository slice; it cannot accept either Proposed ADR, complete the broader DecisionCapsule or ADR-0038 target, or grant runtime authority.

## Limitations
ADR-0093 remains Proposed. Registry v39 Candidate metadata and source copying are not ADR acceptance, architecture compliance, source authenticity, publisher authentication, host isolation, runtime installation, or atomic check-to-use binding. The pinned-golden detector is evidence for one deterministic fixture, not a consumer of arbitrary caller requests.

Generated projects receive no Go or Rust implementation and no runtime registration. Dedicated ReflectionReport attachments remain unresolved opaque declarations on the outer closure; upstream ArtifactRefs remain uninterpreted. No model, rule, world-state, external-history, effect, lifecycle, authority, persistence, PDP, controller, or Reflection consumer is supplied.

The narrow repository-slice completion claim remains false until formal acceptance. The broader `decision_capsule_complete`, ADR-0038, AuthorizedTransactionSpec, authenticated PDP, authority promotion, rolling controller, and runtime replay work remain incomplete even after any later narrow promotion.

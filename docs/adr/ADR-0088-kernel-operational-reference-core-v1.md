# ADR-0088: Kernel Operational Reference Core v1

## Context
The Kernel ABI roadmap names several families of shared objects, but they do not have one safe implementation dependency boundary. Operational references can be frozen and checked without first defining CognitiveAtom expansion or DecisionTransaction. Treating all three as one change would make a broad ABI claim while leaving important semantics and cross-closure relations unimplemented.

Existing Run, Command, Group, bootstrap and Transition records are not suitable aliases. They carry specialized lifecycle, runtime, environment, effect or delivery meanings. The operational core instead needs a small caller-supplied vocabulary that can express inputs, invocation, observations, outputs, retry and a final declared outcome without performing any of those actions.

An object named Receipt is particularly easy to overread. A structural receipt can bind exact declarations and references, but it cannot authenticate a principal or Grant, authorize an operation, append an event, prove execution, attest an outcome or persist state. Those negative semantics must remain machine visible in every record and in the complete reference closure.

## Decision
Adopt five semantic objects: the exact reused `ArtifactRef` triple, `ArtifactReceipt`, `CapabilityInvocation`, `InteractionEvent` and `ExecutionReceipt`. Adopt `KernelOperationalReferenceClosure` only as a nonsemantic fixture and closure-validation envelope. Do not add ExecutionTarget, EnvironmentDigest, EffectRecord, Mobility or ExecutionAttempt. Retry is represented by Invocation `attempt` and `prior_execution_receipt_ref`, followed by the corresponding Receipt `outcome`.

`ArtifactRef` is exactly `artifact_kind`, `artifact_ref` and `artifact_sha256`, matching the value shape used by ADR-0059, ADR-0060 and ADR-0061. The common Principal, TaskBinding and CapabilityIdentity shapes are exact ADR-0056 shapes. CapabilityGrantRef is exactly the ADR-0060 triple `authority_domain`, `grant_id` and `grant_sha256`, with `grant_id` equal to `capability-grant-` plus the digest. ObservedUsage reuses the seven ADR-0058 fields but not its bootstrap-local zero profile: bounded nonnegative call, cost, token, network and byte values may be nonzero.

`ArtifactReceipt` has exactly `api_version`, `artifact`, `artifact_receipt_id`, `artifact_receipt_sha256`, `attestations`, `bindings`, `canonicalization`, `content_bytes`, `created_at_unix_ms`, `kind`, `producer`, `producer_invocation_ref`, `receipt_role`, `slot` and `task_binding`. A declared input has a null producer invocation; a declared output has one exact invocation reference. Producer is an independent caller-declared Principal.

`CapabilityInvocation` has exactly `api_version`, `attempt`, `attestations`, `bindings`, `canonicalization`, `capability`, `capability_grant_ref`, `correlation_id`, `declared_output_slots`, `idempotency_key`, `input_artifact_receipt_refs`, `invocation_id`, `invocation_sha256`, `kind`, `prior_execution_receipt_ref`, `requested_action_sha256`, `requested_at_unix_ms`, `subject` and `task_binding`. Subject is an independent Principal. Attempt one has no prior receipt; attempts two through sixty-four reference the immediately preceding receipt.

`InteractionEvent` has exactly `actor`, `api_version`, `artifact_refs`, `attestations`, `bindings`, `canonicalization`, `causation_event_ref`, `confidence_micros`, `correlation_id`, `event_id`, `event_sha256`, `invocation_ref`, `kind`, `logical_sequence`, `object_ref`, `occurred_at_unix_ms`, `target`, `task_binding` and `verb`. Actor and nullable target are independent exact Principals. Events are ordered by attempt and contiguous logical sequence; after sequence one each cause is the immediately preceding event.

`ExecutionReceipt` has exactly `api_version`, `attempt`, `attestations`, `bindings`, `canonicalization`, `correlation_id`, `ended_at_unix_ms`, `event_refs`, `execution_receipt_id`, `execution_receipt_sha256`, `executor`, `input_artifacts`, `invocation_ref`, `kind`, `observed_usage`, `outcome`, `output_artifact_receipt_refs`, `prior_execution_receipt_ref`, `reason_codes`, `started_at_unix_ms` and `task_binding`. Executor is an independent Principal. The wall interval is nonnegative and at most 86,400,000 milliseconds, and ObservedUsage `elapsed_ms` is exactly the wall interval.

Every semantic record carries the exact opaque binding object `context_sha256`, `environment_profile_id`, `environment_sha256`, `policy_sha256`, `source_profile_id`, `source_revision`, `source_tree_sha256`. These strings and digests are caller declarations only. They create no Environment or Source semantic object and do not authenticate context, source, environment or policy.

Every record and closure carries exactly fourteen booleans, all false: `authorization_attestation`, `binding_authentication_attestation`, `completion_attestation`, `content_provenance_attestation`, `effect_attestation`, `event_append_attestation`, `execution_attestation`, `grant_authentication_attestation`, `outcome_attestation`, `permission_attestation`, `persistence_attestation`, `principal_authentication_attestation`, `transition_attestation` and `usage_measurement_attestation`. No generic truth field replaces these specific negatives.

Record identities are SHA-256 over a NUL-terminated domain followed by compact canonical JSON with both ID and digest empty. The exact domains and prefixes are `forgeos.kernel.artifact-receipt.v1` and `artifact-receipt-`, `forgeos.kernel.capability-invocation.v1` and `capability-invocation-`, `forgeos.kernel.interaction-event.v1` and `interaction-event-`, and `forgeos.kernel.execution-receipt.v1` and `execution-receipt-`. The closure uses `forgeos.kernel-operational-reference-closure.v1` and `kernel-operational-reference-closure-`. An ArtifactRef digest is only an opaque supplied digest; this contract defines no content preimage or provenance for it.

The closure has exactly `api_version`, `artifact_receipts`, `artifacts`, `attestations`, `canonicalization`, `capability_invocations`, `closure_id`, `closure_sha256`, `execution_receipts`, `interaction_events`, `kind` and `result`. Its result is exactly `STRUCTURALLY_VALID_KERNEL_OPERATIONAL_REFERENCE_CLOSURE_V1 (exact caller-supplied records and acyclic references only; no content provenance, principal, Grant, or source/context/environment/policy binding authentication; no authorization, permission, event append, persistence, transition, execution, outcome, completion, effect, or usage measurement attestation)`.

The graph is a forward-only declaration: genesis ArtifactReceipt to Invocation, then Events and output ArtifactReceipt, then ExecutionReceipt, then an optional retry Invocation. ArtifactReceipt never points to an ExecutionReceipt, and Event never points to the final Receipt. Every invocation has exactly one same-attempt receipt; every retry preserves TaskBinding, opaque bindings, capability, Grant reference, correlation, idempotency, inputs, output slots, requested action and subject. A succeeded receipt cannot be retried. Request, start, event, output, end and retry times are monotonically constrained. Within one invocation, Event `occurred_at_unix_ms` values are nondecreasing by logical sequence; equal adjacent timestamps are allowed.

Invocation inputs resolve to included declared-input ArtifactReceipts created no later than the request. Receipt `input_artifacts` is their exact ArtifactRef projection. Declared output slots exactly cover included output ArtifactReceipts produced by the invocation, and Receipt output references exactly cover them. Receipt event references exactly cover the invocation events. Every Event ArtifactRef has at least one included ArtifactReceipt created no later than that event, which prevents a reference to a future-attempt output. The top-level artifact inventory is the exact canonical-byte-sorted union, and no ArtifactReceipt may be orphaned.

Artifact, receipt and event reference arrays may be empty. A closure contains zero through 256 artifacts, zero through 64 ArtifactReceipts, one through 64 invocations, zero through 256 events and one through 64 ExecutionReceipts. Attempts are one through 64. Per-record I/O arrays are at most 32. ArtifactReceipt, Invocation, Event, ExecutionReceipt and closure documents are bounded at 256 KiB, 512 KiB, 256 KiB, 1 MiB and 16 MiB. The wire also bounds depth at sixteen, object fields at sixty-four, arrays at 256, strings at 16 KiB UTF-8, short text at 160 bytes and references at 4,096 bytes.

Python, Go and Rust expose pure canonical, decode, seal and closure-validation APIs and consume no clock, repository, database, network or mutable state. The Python checker accepts either one explicit closure file or the pinned golden. Explicit files must be single-link regular files, are opened with no-follow and checked before, during and after the bounded read; hosts without `O_NOFOLLOW` fail closed. `--golden` resolves the supplied root only to locate and bind the resulting fixture bytes; it does not bind the caller's lexical root spelling. Successful stdout is the exact result marker plus LF.

The JSON Schema is a structural shadow, not the load-bearing accept set. Runtime validators additionally enforce canonical UTF-8 bytes, byte ceilings, reused nested value behavior, ordering, identities, digests, exact projections and time and DAG relations. A change to any field, enum, bound, domain, prefix, marker or graph relation requires a new contract version.

## Consequences
Callers can exchange an exact, portable operational declaration and independently reproduce every record identity and closure seal. The full golden exercises a genesis input, failed first attempt, observations, output, retry and successful final receipt. A second positive profile proves that no-input, no-output and no-event attempts require no invented artifact or observation.

Producer, subject, actor, target and executor remain independent declarations. The closure does not infer that they are equal, authenticated or authorized. Likewise a CapabilityGrantRef is a bound reference shape, not proof that a Grant is authentic, active, applicable or consumed.

The harness package budget rises only from measured actual fifty-one to fifty-two, preserving one file of headroom for the explicit checker while implementation remains split into cohesive packages. No other architecture threshold is relaxed.

Most importantly, this decision is an Operational Reference subclosure only. It does not complete or stabilize the full Kernel ABI and does not justify checking that roadmap item. ADR-0089 governance must keep any full-ABI parent item open; CognitiveAtom expansion, ADR-0090 DecisionTransaction and their cross-closure contract remain prerequisites.

## Validation
The one physical golden and every record digest are pinned in Python, Go and Rust. Each implementation decodes and exactly reseals all four record types and the closure and accepts the empty-I/O profile. Cross-contract tests use the existing ADR-0056, ADR-0058, ADR-0059, ADR-0060 and ADR-0061 Schemas as source-shape oracles and then mutate the operational runtime seal path; this is Schema-source plus operational-runtime evidence, not a claim of two runtime validators or of inherited upstream regex behavior.

Strict tests reject duplicate, unknown and missing fields, floats, non-finite values, invalid UTF-8, controls, C1, bidi scalars, isolated surrogates, U+2028, U+2029, signed-int64 overflow, noncanonical whitespace and framing. Depth, field, array, UTF-8 string and each standalone document ceiling are checked at the boundary and N-plus-one. Nested Principal, TaskBinding, CapabilityIdentity, CapabilityGrantRef, ArtifactRef and ObservedUsage mutations cover missing, extra, enum, digest, type, boolean and negative-number drift.

Graph tests cover empty sets, attempt and cardinality N and N-plus-one, retry predecessor and success termination, unresolved references, task and binding drift, input and output projection, event correlation and causation, wall usage mismatch, output timing, orphan receipts, inventory completeness and the exact nonfuture Event artifact boundary.

Run Python focused tests with bytecode disabled, Go focused and race tests, Go vet and formatting, Rust focused tests, formatting and lint, strict ADR v2 validation and architecture checks. Verify every owned file is regular mode `0644` with link count one, the Python package contains no cache and the final Schema, ADR, golden and source pins are stable. Independent semantic review is required before the implementation is called a frozen candidate.

## Limitations
ADR-0088 remains Proposed. Its SUCCESS marker means only that supplied records and their declared references are structurally and cryptographically self-consistent. It does not authenticate content provenance, a principal, Grant or opaque binding; authorize an action; grant permission; append an event; execute a capability; attest an outcome, completion, effect or usage measurement; perform a transition; or persist any record.

The checker is not a product command, Registry capability, runtime adapter, event store, journal, database writer, network service or scaffold distribution. The explicit file boundary protects only that local read; it does not authenticate the file's producer or repository snapshot. The golden root's resolved fixture bytes are pinned, not the caller's lexical path identity.

This decision intentionally omits ExecutionTarget, EnvironmentDigest, EffectRecord, Mobility, ExecutionAttempt and all specialized Run, Command, Group, bootstrap and Transition aliases. Environment, source, context and policy remain opaque bindings. There is no cross-closure CognitiveAtom or DecisionTransaction rule here.

Therefore neither this decision nor its future governance companion may mark the roadmap checkbox for the complete Kernel ABI. That checkbox can be reconsidered only after CognitiveAtom expansion, ADR-0090 DecisionTransaction and an explicit compatible cross-closure definition are implemented and independently reviewed.

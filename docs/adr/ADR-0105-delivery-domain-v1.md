# ADR-0105: Delivery Domain v1

## Context
R0-C2 provides a durable internal Workspace Catalog for Space, Project and declared ProjectSnapshot references. The next forge-core task, FC-05, needs Objective, Change, AcceptanceCriteria, WorkGraph and WorkItem semantics before a Reconciler, transport or UI can depend on those names. Encoding those rules directly in a future API or legacy graph adapter would make transport maps and historical orchestration files accidental product-domain authority.

The adversarial product plan explicitly limits the first Objective and Change model to the Go control plane. Freezing another cross-language protocol before a real Go consumer exists would increase compatibility cost without unlocking Runtime or Harness behavior. Conversely, combining this domain slice with persistence, authentication, ready-node selection, Attempt dispatch or completion joins would make it impossible to review deterministic planning rules separately from authority and effects.

The repository-level proof that this mutable package has no production consumer runs a bounded offline Go metadata process and parses machine output. Review of that proof exposed shared subprocess failure modes that could otherwise turn cancellation, byte-count overflow, truncation or an inherited pipe into a usable result. R0-C3 therefore also includes a scoped hardening of the existing internal bounded executor and its machine-parsing consumers. This is supporting repository infrastructure, not a Delivery application consumer or a claim that subprocesses are contained.

## Decision
Add one pure Go package at forge-core/internal/delivery/domain. It defines bounded Objective, Change, AcceptanceCriterion, SnapshotBinding, BudgetLimit, WorkGraph and WorkItem values plus pure validators. It reuses Platform Core typed references and WorkItem state vocabulary but introduces no canonical JSON, CommandEnvelope, EventEnvelope, database schema, migration or cross-language wire. Callers supply all identities, actors, timestamps, states and values; the domain neither generates nor persists them. These aggregates are caller-owned mutable drafts. Callers must keep the complete reachable slice and pointer graph race-free and stable for the full validation call; validators neither synchronize nor deep-copy and do not create an atomic snapshot or durable validated token. R0-C3 admits no production consumer; a later consumer must establish defensive ownership or revalidate its exact stable value at the operation boundary.

Harden forge-core/internal/execbound for the bounded metadata proof and its existing callers. Arbitrary streaming stdin becomes copied in-memory stdin capped at 16 MiB; ordinary combined capture connects stdout and stderr to one shared raw pipe, while observed capture retains its separately tagged producer-serialization contract. Raw drains have an all-platform two-second parent-reader backstop, `Result` exposes saturated signed-64 count overflow and incomplete drain separately, and cancellation cannot project as success. On Linux hosts where `waitid(WNOWAIT)` is available, cancellation serializes group `SIGKILL` with reaping so a released and reused numeric PGID is never signalled; other targets use direct-child kill. Process groups remain explicitly best-effort teardown rather than containment; normal parent exit does not signal descendants. Gate JSON and Git metadata parsers fail closed on every relevant degradation. Existing orchestrator, gate, observation, project-snapshot, worktree-source and session-worktree callers are updated together; none imports the Delivery package.

Apply the same fail-closed completion rule at the sandbox caller boundary: the immediate context sample after `Runner.Run` returns is the linearization point, and a cancellation or deadline already visible there suppresses validation, durable output commit and observation even when a faulty runner reports nil error and exit zero. Docker and Firecracker host counters use saturating signed-64 totals. Firecracker no longer derives command output, completion or exit status from workload-forgeable serial sentinels or a guest-writable marker. A `0700` trusted PID-1 script creates a fresh randomized root-only result directory, opens the output, verifies an exact `/bin/setpriv` profile, and runs the workload as uid/gid 65534 with no-new-privs and empty inheritable, ambient and bounding capability sets. PID 1 atomically writes a strict status after the workload exits and powers off; the host waits for actual VMM exit before bounded debugfs export of status and exact output. Serial bytes remain bounded diagnostics only. The rootfs and its compatible setpriv implementation are explicit operator-trusted TCB inputs, and this remains an argv/stdin/output runner rather than a coding-workspace exchange protocol.

An Objective binds one Space to a bounded title, desired outcome, constraints, target Project set, success measures, caller-declared creator, state and positive version. A Change must reference a valid Objective and exact parent version, preserve its Space and target Project set, bind exactly one declared ProjectSnapshot per target Project, provide bounded acceptance criteria, an optional unresolved impact RecordRef, a policy-profile declaration, total attempt and micro-USD ceilings plus a longest-dependency-path duration ceiling, caller-declared proposer, desired state, observed state and positive version. Desired and observed state are separate vocabularies and transition validators only recognize declared edges; they do not read current state or authorize a transition.

A WorkGraph references the same Space, Objective, exact Change version and Change and repeats the exact Change snapshot bindings. It contains one through 128 WorkItems and at most 512 dependency edges. Every WorkItem has a typed ID, purpose, exact target ProjectSnapshot, at least one valid acceptance-criterion reference, at least one verification requirement, requested-effect declarations, risk, optional structurally valid context ArtifactRef, requirements, Platform Core WorkItem state and a bounded budget. All Change criteria and their declared verification requirements must be covered by referencing WorkItems, aggregate attempt and cost limits must fit the Change budget, and the overflow-safe sum of WorkItem duration ceilings along every dependency path must fit the Change duration.

Graph validation rejects duplicate or missing nodes, self-dependencies, cycles, unsupported state or risk, invalid references, criterion or verification gaps, snapshot substitution, aggregate or critical-path budget overflow and all collection or text bounds. A lexicographically deterministic Kahn traversal makes topological order independent of input item order. It is not ready-node selection and grants no execution authority. State-edge functions are pure vocabulary checks analogous to the Platform Core state contract; a successful check is not evidence that a current state, Approval, Receipt or Outcome permits the edge.

CompareSnapshotBindings compares two caller-supplied Project-to-ProjectSnapshot identifier sets and returns sorted missing, changed and unexpected Project IDs. Equality means only that the supplied declarations match. The package never stats or opens a path, runs Git, discovers a current Snapshot or proves freshness, repository identity, completeness or secret safety. Repository tests enforce an exact Delivery direct-import allowlist and scan direct import paths in the finite Platform Core reference/state/wireprofile source set, rejecting new filesystem, process, network, storage, clock and randomness package paths. The guard constrains dependency paths; it does not attest the behavior of every API in already permitted packages such as fmt or io. It is not an atomic compiler-byte attestation, call-level effect analysis, runtime sandbox or check-to-use guarantee.

This slice adds no application service, repository, projection or public route. It does not create Objective, Change or WorkGraph journal history and cannot make any product mutation survive restart. Those behaviors require separate decisions for canonical payloads, optimistic replay, actor authentication, policy authority, current Snapshot ownership, Reconciler decisions and completion evidence.

## Consequences
The Go control plane gains a deterministic, bounded business model for planning one Objective into a snapshot-bound Change and WorkGraph. Later application, Reconciler and compatibility adapters can consume typed values instead of duplicating DAG, criterion, budget and snapshot rules. Randomized and adversarial tests can examine the planning core without SQLite, subprocesses, credentials, Runtime or Harness fixtures.

Existing Platform Core bytes, control.db schema v1, Workspace journal behavior, App Server health, Runtime and Harness databases, CLI output contracts and graph protocols remain unchanged. The Delivery package and execbound are internal-only APIs. Within forge-core, `execbound.Spec.Stdin` now requires bounded bytes instead of an arbitrary Reader, ordinary combined capture has explicit shared-pipe ordering, and context failure, count overflow, truncation and incomplete drain can newly fail closed instead of yielding a usable result. All in-repository callers are migrated in the same tree; there is no durable state or wire migration.

Firecracker configuration compatibility is intentionally stricter: a rootfs that lacks the exact setpriv privilege-drop profile now fails closed, old marker-based host evidence proves only the external KVM/Firecracker prerequisite, and hardened result-channel live verification requires an updated rootfs. Successful output retains exact result-file bytes instead of trimming or parsing serial framing. Docker and Firecracker over-limit diagnostics now preserve cross-platform signed-64 accounting, and sandbox cancellation visible at the defined linearization point can newly turn an apparent runner success into `KindFailed` or `KindTimeout` before any accepted-output side effect.

The strict shape rules intentionally reject partial plans rather than repair, sort or infer them. This may require future application code to collect missing criteria, snapshots or budgets before validation. That friction is desirable at the pure boundary but is not user experience and does not establish that the plan is useful, authorized or executable.

## Validation
Unit and table tests cover every text, identifier, reference, timestamp, version, state, risk, budget and collection boundary. Mutation tests attack controls, format characters, duplicate text and IDs, Objective/Change ancestry and parent versions, target Project coverage, snapshot substitution, criterion and verification references, Artifact source Snapshot relations, malformed or duplicate requested-effect declarations and arithmetic overflow. Transition matrices exercise every declared legal edge and representative unknown, reverse and terminal edges without treating validation as state mutation.

DAG tests cover empty, bounded, duplicate, self, missing, cyclic, disconnected and dense graphs. A deterministic randomized suite generates many DAG permutations, verifies the same lexicographic topological order and injects a back edge to force cycle rejection. Complete validation exercises all 24 WorkItem orderings plus reversed set-like Objective, Change, WorkGraph and WorkItem declarations. Budget and criterion properties prove exact and over-limit aggregate attempt/cost, diamond longest-path duration and scoped criterion-verification coverage. Criterion-map diagnostics are independent of runtime map order, and WorkItem validation uses bounded ID order; this does not make every multi-defect malformed declaration ordering one canonical diagnostic. Snapshot comparison tests cover exact match plus sorted missing, changed and unexpected declarations while retaining the no-freshness claim.

A production-source boundary test rejects symlinked roots/files, hard-linked files, native or non-Go compiled artifacts and nested production packages. It binds the exact module-relative package root, pre-reserves each stable file size against a 256 MiB aggregate budget before opening or reading, then checks opened-file identity, exact size and metadata before and after each bounded read. Unix link counts come from `Stat_t`; Windows counts come from `ByHandleFileInformation` on a file handle. The guard scans every non-test regular Go file regardless of build tags, uses exact untrimmed import paths, and checks direct imports in the finite Platform Core dependency-source set. A whole-module lexical scan includes testdata and every build-tag source while rejecting every module symlink; it deduplicates consumers per source file, bounds retained path count and emits only escaped length-capped examples. Linux, Darwin and Windows offline `go list -e -json ./...` runs parse local production-package direct-import metadata with empty HOME/module/build caches. The `-e` mode retains local metadata when external modules are unavailable, while the environment disables all network and VCS resolution. The resolved `GOROOT/bin/go` path is a trusted host TCB and is path-pinned, not open-file-identity or digest pinned. It runs through race-free cancellation-only best-effort process-group teardown on supported Linux hosts, direct-child kill elsewhere and an all-platform bounded parent-reader drain backstop, with aggregate output, escaped diagnostic and time bounds and a closed environment that disables module proxy, checksum service, VCS, toolchain download and inherited proxy settings. Source checks require one frozen, quiescent tree and do not form an internally atomic source snapshot: same-inode, same-size writes with restored timestamps or reverted directory churn during a scan remain outside the guarantee. They also do not claim atomic identity with later compiler reads or effect-freedom of every call in an allowlisted dependency.

Shared-executor tests cover pre-cancelled and raced cancellation, Linux group teardown serialized against reap, non-Linux direct-child teardown, escaped inherited writers, abnormal exit plus incomplete drain, one-pipe combined write order, bounded stdin, exact truncation and signed count saturation. Gate and Git parser regressions reject incomplete drain, overflow and truncation before interpreting retained bytes. Focused and full Go normal/race/vet/build, formatting, cross-build, architecture, governance, two fresh-context reviews and formal repository acceptance run on the frozen completion tree. No live provider, credential, project path, external network, Runtime process, Harness execution or browser is used.

Sandbox regressions synchronize cancellation before a runner's nil/zero return and prove that validators, durable commit and Observe are not called. Docker and Firecracker tests inject near-MaxInt64 totals without large allocation. Firecracker tests reject the old marker/sentinel protocol, require the unprivileged no-capability launcher, preserve former sentinels and NUL as ordinary exact output, reject malformed or multi-record status, enforce randomized closed path grammar and bounded regular-file reads, and cross-compile on Linux, Darwin and Windows. The live KVM tests remain environment-gated; absence of the updated setpriv-capable rootfs is reported as skipped rather than represented as hardened transport evidence.

## Limitations
This candidate does not define canonical Objective, Change, WorkGraph or WorkItem command/event payloads, replay folds, expected-version behavior, idempotency, durable identity generation, repository APIs, schema v2, projection or migration. Values validated here disappear unless a later application boundary persists an independently reviewed event history.

No actor is authenticated, no policy profile or requested effect is resolved, and no Approval, Grant, ImpactAssessment, Artifact or Snapshot reference is looked up. State validators neither observe nor change current state. Topological order does not select a ready WorkItem, and no Agent, Runtime, Harness or Reconciler can be invoked through this package. Successful validation cannot be retained as authority over a draft that is later mutated; concurrent mutation is a caller data race, and any future production consumer requires a separately reviewed ownership or boundary-revalidation rule. Source allowlists detect package-path drift but are not semantic effect proofs for already admitted APIs, and a source scan with a concurrent writer carries no trustworthy snapshot claim. Only the error relation is stable; different orderings of a multi-defect malformed declaration can select different non-wire diagnostic details outside the explicitly ordered checks.

The shared executor does not sandbox filesystem, network, credentials, syscalls or descendant processes. On cancellation, supported Linux hosts serialize process-group `SIGKILL` with reaping and normally reach members that remain in the group without risking a stale PGID signal; other targets kill only the direct child. Normal parent exit sends no descendant signal, and an escaped or remaining descendant may survive on every platform. The raw-drain deadline closes only the parent's capture readers to prevent an inherited writer from hanging the caller and reports incomplete observation; it does not close descendant writers or prove descendant death or complete effects. Observed combined output records producer serialization of separately drained streams, not the child or kernel's original cross-stream emission order.

The hardened Firecracker result protocol prevents the workload from directly writing trusted status under the declared rootfs and Linux privilege profile; it does not attest the rootfs publisher, setpriv binary, kernel or VMM, prevent kernel/TCB exploitation, supply repository mounts or secrets, or turn Firecracker into remote exactly-once execution. The command can control its own output bytes and direct exit code. If PID 1 cannot create or persist the private status, or the VMM exits abnormally, the host fails closed rather than accepting serial text or a stale template file.

There is no Receipt or AcceptanceCriteria completion join. Runtime terminal text, an ExecutionReceipt, a VerificationReceipt or a structurally valid transition cannot by itself complete a WorkItem, Change, Objective or Outcome. FC-06 and later vertical slices must separately define deterministic current-state inputs, evidence freshness, authority, recovery and failure semantics.

ADR status remains Proposed. Structural validity, passing tests, declared owners and repository acceptance are implementation evidence for this narrow candidate; they are not authenticated adoption, product readiness, architecture compliance, authorization, truth or completion authority.

# ADR-0089: Kernel Operational Reference Governance and Source Distribution

## Context
ADR-0088 freezes five authority-neutral operational reference objects and one nonsemantic closure across dependency-free Python, Go and Rust. It validates caller-supplied declarations and an acyclic retry and artifact graph, but it neither executes an invocation nor authenticates a principal, Grant, binding, event, outcome or receipt.

The reviewed Python implementation is portable to generated projects. The Go and Rust implementations are valuable independent parity evidence inside Catalyst, but copying them would imply runtime capability and toolchain ownership that source distribution does not provide. Active governance therefore needs a scope-neutral candidate boundary that distinguishes portable source from repository-only evidence.

The checker requires an explicit mode. Registry wiring can honestly execute the pinned golden as `python3 harness/kernel_operational_contract_check.py --golden .`; it must not invent stdin, a runtime request, a route or an ambient consumer.

## Decision
Adopt Registry v37 with one `kernel_operational_reference_core_v1_candidate_contract` block. Keep the complete Registry scope mapping and canonical scope digest unchanged. Do not add ArtifactReceipt, CapabilityInvocation, InteractionEvent, ExecutionReceipt or the closure to shipped or planned kinds, evaluators, producers, projectors, adapters or runtime profiles.

Register exactly one non-load-bearing shadow detector. Its argv is exactly `python3 harness/kernel_operational_contract_check.py --golden .`, cwd is `repo_root`, shell mode is false and invocation owner is the operator. The detector validates only the byte-pinned golden already governed by this candidate. The checker's separately available `--file` mode does not create a Registry data plane or runtime integration.

Source distribution is exactly eighteen files: ADR-0088, its Schema and golden, the exact eight-file Python package, checker, three focused Python tests, this decision, and its governance module and test. Generated projects receive none of `forge-core/internal/kerneloperationalcontract`, the Rust domain module or registration, a runtime binary, route, Skill, service, database, journal, state, key, Grant or authority artifact.

The positive result remains the exact ADR-0088 structural marker, and all fourteen attestations remain false. Registry evidence pins the exact Python twelve-file aggregate and fifteen-file source core, the Catalyst-only Go eleven-file aggregate and Rust module-directory thirteen-file aggregate, the physical decision, Schema and golden, and the semantic closure seal. The shared Rust `domain/src/lib.rs` is not whole-file pinned or included in that aggregate; governance only requires its regular `0644`, single-link bytes to contain exactly one `pub mod kernel_operational_contract;` line so unrelated module registrations can coexist.

## Consequences
Catalyst and generated projects can independently reproduce the same pure operational closure. Generated dependency-free tests retain the load-bearing canonical and graph corpus; optional Schema parity tests skip honestly when `jsonschema` is unavailable under `python -S`.

Registry v37 adds no authority or execution surface. Producer, subject, actor, target and executor remain independent caller declarations; Grant and binding references remain unauthenticated; receipt-shaped records remain declarations rather than proof of event append, persistence, execution, outcome, completion, effect or usage measurement.

The complete Kernel ABI roadmap item remains unchecked. CognitiveAtom source, type, authority and hardness expansion, DecisionTransaction and their explicit cross-closure contract remain prerequisites for any later full-ABI decision.

## Validation
Recompute the ADR-0088 physical decision, Schema, golden, closure seal, exact Python twelve-file and source fifteen-file aggregates, Go eleven-file aggregate and Rust module-directory thirteen-file aggregate. Verify the Rust operational registration is present exactly once without pinning unrelated `lib.rs` bytes. Run all forty Python tests with optional dependencies, the dependency-free generated profile, all focused Go tests with race and vet, and the focused Rust package tests and lint.

Mutation-test Registry v37 version, unchanged scope and scope digest, candidate block, refs, pins, implementation classifications, fourteen false attestations, non-capability and exact detector argv. Reject route, Skill, runtime, authority, stdin, arbitrary file, Go or Rust distribution promotion.

Validate exact eighteen-file fresh generation and a real Registry v36 inverse projection. Require regular mode `0644`, link count one, no-follow source and target reads, fixed hashes, exact ledger ownership, absent Go and Rust trees, all older slice verifiers green under active v37, a clean second upgrade and the normal architecture, complexity, security and acceptance gates.

## Limitations
ADR-0089 remains Proposed. It does not authenticate any principal, Grant, artifact content, source, context, environment or policy binding. It does not authorize, append, persist, transition, execute, attest outcome or completion, measure usage, or produce an effect.

The pinned-golden detector is evidence for one deterministic fixture, not a consumer of arbitrary operational requests. The explicit-file checker remains a standalone pure validator and has no check-to-use handoff, caller authentication, repository snapshot binding or runtime ownership.

Generated projects receive no Go or Rust implementation and no runtime registration. This decision does not expand CognitiveAtom, define DecisionTransaction, integrate any operational object with a controller or close the complete Kernel ABI roadmap parent.

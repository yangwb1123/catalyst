# ADR-0086: Legacy Governance Read-only Import v1

## Context
ForgeOS contains historical governance-shaped data that predates authenticated authority contracts. The memory JSONL format permits an omitted confidence value that the current runtime defaults, and its load path filters entries named by later supersede declarations. Historical ADR Markdown can also contain words such as Accepted or Superseded without an authenticated approval receipt or lifecycle transition. Reading those runtime views would erase evidence about what was actually present and could falsely promote old labels into current truth.

The safe precursor to any future migration is narrower: preserve explicit bytes and declarations so they can be inspected, compared and later adjudicated. This slice must not decide which entry is correct, current or authoritative. It must not read an ambient repository, reuse `memory.Load`, retroactively validate old Markdown as ADR v2, produce a Claim or Atom, or write a new state.

Cross-project identity is part of that boundary. A source reference and raw digest can repeat across projects or revisions. A candidate is therefore reusable only within the exact project and source snapshot named by the public request.

## Decision
Adopt `forgeos.legacy-governance-read-import-request/v1` as the only public input and `forgeos.legacy-governance-read-import-view/v1` as its unique pure output. The public request wire is one compact canonical JSON document followed by exactly one LF and nothing else. The projector consumes supplied bytes to EOF; it accepts no path, repository root, clock, database handle or implicit source.

The request has exactly `api_version`, `binding`, `canonicalization`, `kind`, `request_sha256` and `sources`. Its binding has exactly `project_id`, `source_revision` and `source_tree_sha256`; the first two are bounded closed ASCII identifiers and the tree value is lowercase SHA-256. Each source has exactly `byte_count`, unpadded RFC 4648 `content_base64url`, `content_sha256`, `source_kind` and opaque `source_ref`. Sources are unique and raw-UTF-8 ordered by `(source_kind, source_ref)`. The supported kinds are one optional `forgeos_memory_jsonl_v1` source and zero through two hundred fifty-six `legacy_adr_markdown` sources, with at least one source overall.

`request_sha256` is SHA-256 of the NUL-terminated domain `forgeos.legacy-governance-read-import-request.v1` followed by the compact canonical request object with only `request_sha256` replaced by the empty string. The LF stream delimiter is not part of this semantic digest. Because the binding is inside that preimage and every candidate locator includes `request_sha256`, identical source bytes and references in another project, revision or source tree have different candidate identities.

Decoded sources must be strict UTF-8, contain no CR and end in LF. The memory source is at most thirty-two MiB, contains at most 4,096 nonblank LF-delimited object lines, and each line is at most sixteen MiB. Every line rejects duplicate and unknown fields and has exactly the historical optional set `_format`, `source`, `confidence` and `supersedes` plus required `kind`, `topic`, `detail`, `iteration` and `created_at_unix`. `_format`, when present, is exactly `forgeos.memory.v1`; kind is `gap`, `decision` or `lesson`; integer fields are signed int64. Confidence is either omitted or an explicit finite JSON number in decimal range zero through one. Its presence and original number lexeme are preserved without float conversion, normalization or defaulting. Source and supersede are preserved when explicitly present. No row is discarded or reordered.

Each ADR source is at most one MiB. It becomes one candidate containing the complete supplied document bytes and ordinal one. The projector does not parse its title, frontmatter, status, supersession wording or ADR version; `parsing` is exactly `not_performed`. In particular, historical Accepted and Superseded text remains unauthenticated raw data.

Every candidate contains its source kind and reference, one-based physical ordinal, raw byte count, unpadded base64url, raw SHA-256, request SHA-256, request-bound candidate ID and self digest. A memory candidate also carries the declared fields and confidence-presence object; an ADR candidate carries only its document name and no-parse marker. Every candidate is forced to `trust_state:unverified_legacy`, `current:false`, `hardness:none`, `instruction_allowed:false` and `authority:null`. Candidate IDs use the NUL-terminated `candidate-id.v1` domain over request digest, source kind, source reference and ordinal. Candidate seals use the distinct `candidate.v1` domain with only `candidate_sha256` empty.

The view repeats the exact binding and request digest, lists source descriptors, candidates, complete duplicate `(declared_kind, declared_topic)` memory conflict groups and every nonempty declared supersession. Conflict groups are ordered by kind and topic; their member candidate IDs are raw-UTF-8 sorted and unique because membership is a set, while the top-level candidate array retains source and physical ordinal order. Conflict and supersession relations are sealed under distinct domains and supersessions are always `unresolved_unverified_legacy`; neither relation selects or removes a member. The descriptor-set digest uses its own domain. The view self digest uses `forgeos.legacy-governance-read-import-view.v1` with only `view_sha256` empty. Its result is `PROJECTED_UNVERIFIED_LEGACY_READ_ONLY`. Acceptance, authority, confidence interpretation, conflict resolution, currentness, instruction eligibility, persistence, runtime effect, source authentication, source completeness, status interpretation, truth and winner-selection attestations are all false.

The exact optional human-facing marker is `STRUCTURALLY_VALID_LEGACY_GOVERNANCE_READ_IMPORT_V1 (unverified legacy read-only projection only; no source authentication or completeness, confidence or status interpretation, conflict resolution, truth, authority, currentness, instruction, acceptance, persistence, winner, or runtime-effect attestation)`. It denotes only successful structural validation and carries the same thirteen false semantics. It is frozen as Schema metadata and language constants, is not a view field, and is not emitted by the checker: successful checker stdout remains the exact canonical view plus one LF.

Validation reconstructs each memory source from its ordered raw lines plus LF and each ADR from its single whole-document candidate, then compares exact bytes, counts and digests to the request. It also reprojects and requires byte-identical canonical view output. Request and view reject duplicate or unknown fields, noncanonical JSON, invalid UTF-8 or base64url, bad ordering, inconsistent counts or digests and partial consumption.

The aggregate supplied raw-byte ceiling is sixty-four MiB; request wire and view document ceilings are ninety-six and one hundred twenty-eight MiB. Source references are at most 4,096 UTF-8 bytes, binding identifiers 160 bytes, confidence lexemes 128 bytes, canonical strings forty-eight MiB, JSON depth sixteen, object fields thirty-two and arrays 4,352 items. A change to a field, bound, order, domain, source profile or framing requires a new contract version.

The Python package exposes only strict request and view decoders, a pure request builder for already supplied bytes, the projector and request-bound validator. Its zero-argument checker reads the exact request from stdin and writes the canonical view plus one LF. The Go package exposes only `DecodeRequest`, `Project`, `DecodeView` and `ValidateViewAgainstRequest`. Neither implementation imports the memory runtime, reads a path, discovers a repository, consults a clock, caches, defaults, filters, persists or mutates.

## Consequences
An audit or later migration design can retain every historical row, conflict, supersede string and ADR byte without implying that any of them is correct. Omitted confidence remains omitted; explicit `0`, `1e-7` and `1.000000` remain distinct evidence. Old status words remain readable but inert.

The request digest binds that evidence to one named project snapshot, and candidate seals bind to the whole request rather than only a potentially reusable source reference. Source reconstruction and one cross-language golden make silent normalization or filtering observable.

The result is intentionally not a governance database or compatibility adapter. A caller must separately authenticate sources and authorize any promotion, persistence or lifecycle operation. Deleting this pure slice changes no legacy source and rolls back no state.

## Validation
The fixed request embeds one four-line memory source and two legacy ADR documents. It exercises an omitted confidence, explicit `0`, exponent `1e-7`, trailing-zero `1.000000`, two conflicting database decisions, one supersede declaration, Chinese historical status text and English Superseded text. Python and Go must both produce the exact same six-candidate canonical output, request digest, source-set digest, candidate identities and seals, one unresolved conflict group, one unresolved supersession and view digest.

Focused tests reject missing or duplicate terminal framing, leading or trailing JSON whitespace, duplicate and unknown keys, unordered or duplicate sources, malformed base64url, byte-count and digest drift, invalid UTF-8, CRLF, blank JSONL lines, missing final LF, bad memory shapes, non-int64 integers and confidence outside zero through one. View tests mutate forced authority fields, raw bytes, counts, digests, ordinals, relations, source reconstruction, binding and request identity.

Run the Python focused suite and exact checker comparison. Run Go focused tests, race detection, vet and formatting. Run strict ADR v2 validation, Schema parse, architecture checks, file and function caps, Go export cap, regular-file mode `0644`, link count one, cache absence and diff hygiene. An independent reviewer must inspect semantic parity, digest acyclicity, raw preservation, cross-project binding and negative authority and persistence boundaries before pins are final.

## Limitations
ADR-0086 remains Proposed. It does not authenticate source provenance, attest that the supplied binding is truthful, verify a repository tree, validate an old ADR as ADR v2, resolve a conflict or supersession, select a current winner, accept or supersede an ADR, issue a Claim or Atom, create an instruction, grant permission, perform a transition or persist any result.

The checker is not a product command, service, route, socket, registry capability, scaffold artifact or memory-runtime integration. No generated project receives this slice through this decision. There is no ambient repository fallback, recursive discovery, path identity protection, database, cache, network, clock, trusted signer or authenticated caller.

Raw preservation can show what bytes and declarations were supplied, not whether their source is authenticated, whether the supplied set is complete, whether confidence or status should have a particular interpretation, or whether a conflict is resolved. Any future authority-bearing promotion must consume this view only as untrusted evidence and introduce a separate authenticated authorization, currentness, idempotency, transition, persistence, recovery and audit contract.

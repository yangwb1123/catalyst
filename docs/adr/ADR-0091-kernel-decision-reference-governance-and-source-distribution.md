# ADR-0091: Kernel Decision Reference Governance and Source Distribution

## Context
ADR-0090 freezes CognitiveAtom v2, DecisionTransaction v1 and a one-way nonsemantic closure over the exact ADR-0088 operational reference records. It supplies the structural reference-family candidate needed by the Kernel ABI, but governance acceptance remains pending and it neither authenticates any declared source or authority nor turns hardness, instructions, events, receipts or usage declarations into policy or execution facts.

The dependency-free Python implementation is portable to generated projects. The Go and Rust implementations provide independent parity evidence inside Catalyst, but copying them would imply runtime and toolchain ownership that source distribution does not provide. Active governance therefore needs a scope-neutral candidate boundary that distinguishes portable source from repository-only evidence.

The checker requires an explicit mode. Registry wiring can honestly execute the pinned golden as `python3 harness/kernel_decision_contract_check.py --golden .`; it must not invent stdin, a runtime request, a route or an ambient consumer.

## Decision
Propose Registry v38 with one `kernel_decision_reference_core_v1_candidate_contract` block. Keep every Registry scope array and the canonical scope digest unchanged. Do not add CognitiveAtom v2, DecisionTransaction, InteractionEvent, CapabilityInvocation, ArtifactReceipt, ExecutionReceipt, the operational closure or the decision closure to shipped or planned kinds, evaluators, producers, projectors, adapters or runtime profiles.

Register exactly one non-load-bearing shadow detector. Its argv is exactly `python3 harness/kernel_decision_contract_check.py --golden .`, cwd is `repo_root`, shell mode is false and invocation owner is the operator. The detector validates only the byte-pinned golden governed by this candidate. The checker's separately available `--file` mode does not create a Registry data plane or runtime integration.

Source distribution is exactly nineteen files: ADR-0090, its Schema and golden, the exact nine-file Python package, checker, three focused Python tests, this decision, and its governance module and test. Generated projects receive none of `forge-core/internal/kerneldecisioncontract`, the Rust domain module or registration, a runtime binary, route, Skill, service, database, journal, state, key, Grant, Approval, PDP or controller artifact.

The positive result remains the exact ADR-0090 structural marker, effective hardness remains `none`, instructions remain disabled and all twenty-two attestations remain false. Registry evidence pins the exact Python thirteen-file aggregate and sixteen-file source core, the Catalyst-only Go thirteen-file aggregate and the flat Rust nine-file aggregate. Rust test modules remain normal focused evidence rather than part of the flat source pin. The shared Rust `domain/src/lib.rs` is not whole-file pinned or included in that aggregate; governance requires only its regular `0644`, single-link bytes to contain exactly one `pub mod kernel_decision_contract;` line so unrelated module registrations can coexist.

The implementation roadmap narrows the Kernel structural reference-family ABI item but keeps it open pending candidate acceptance by `forge accept`. ADR-0038 remains `ADOPTED-PARTIAL`; DecisionCapsule, AuthorizedTransactionSpec, authenticated Grant/PDP promotion and rolling controller semantics remain open.

## Consequences
Catalyst and generated projects can independently reproduce the same pure decision and operational reference closure. Generated dependency-free tests retain the load-bearing canonical, role, source, transaction, budget and cross-closure corpus; optional Schema parity tests skip honestly when `jsonschema` is unavailable under `python -S`.

Registry v38 adds no authority or execution surface. Source, authority, hardness, role, subject, actor, target and executor remain caller declarations. Grant, Approval, binding, event and receipt references remain unauthenticated. Receipt-shaped records remain structural inputs rather than proof of append, persistence, execution, outcome, completion, effect or measured usage.

Future acceptance of the structural reference-family item would not accept ADR-0038 as complete and would not deliver DecisionCapsule, AuthorizedTransactionSpec, a policy decision point, authority-bearing lifecycle promotion, a controller or reflection runtime.

## Validation
Recompute the ADR-0090 physical decision, Schema, golden, closure seal, exact Python thirteen-file and source sixteen-file aggregates, Go thirteen-file aggregate and flat Rust nine-file aggregate. Verify the Rust decision registration is present exactly once without pinning unrelated `lib.rs` bytes. Run focused Python tests with and without optional dependencies, all focused Go tests with race and vet, and the focused Rust package tests and lint.

Mutation-test Registry v38 version, unchanged scope and scope digest, candidate block, refs, pins, implementation classifications, twenty-two false attestations, ineffective hardness and instructions, non-capability and exact detector argv. Reject route, Skill, runtime, authority, stdin, arbitrary file, Go or Rust distribution promotion.

Validate exact nineteen-file fresh generation and a real Registry v37 inverse projection. Require regular mode `0644`, link count one, no-follow source and target reads, fixed hashes, exact ledger ownership, absent Go and Rust trees, all older slice verifiers green under active v38, a clean second upgrade and the normal architecture, complexity, security and acceptance gates.

## Limitations
ADR-0091 remains Proposed and its governance candidate has not yet been accepted by `forge accept`. It does not authenticate any source, principal, Approval, Grant, artifact content, context, environment or policy binding. It does not authorize, append, persist, transition, execute, attest outcome or completion, measure usage, or produce an effect.

The pinned-golden detector is evidence for one deterministic fixture, not a consumer of arbitrary decision requests. The explicit-file checker remains a standalone pure validator and has no check-to-use handoff, caller authentication, repository snapshot binding or runtime ownership.

Generated projects receive no Go or Rust implementation and no runtime registration. This decision does not implement DecisionCapsule, AuthorizedTransactionSpec, PDP, controller, authority-bearing promotion or reflection. ADR-0038 remains ADOPTED-PARTIAL.

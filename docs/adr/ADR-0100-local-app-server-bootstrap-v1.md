# ADR-0100: Local App Server Bootstrap v1

## Context
Forge Workspace needs one stable process boundary before a CLI, TUI or Web client can share commands, queries and a durable event stream. The current repository has strong Go orchestration, Rust execution and Harness verification assets, but no App Server binary. Adding Objective, Change, WorkGraph, Runtime ingestion and UI state in one change would hide lifecycle and transport mistakes inside a much larger product surface.

The first slice therefore establishes only local process reachability. It must not reinterpret existing workflow, Graph, Run, approval or verification records, and it must not create a second source of product truth. A health response is useful for installers and later clients, but it is not evidence that Runtime, Harness, a project or any external provider is ready. The caller-selected state path and local HTTP socket are still security boundaries even though the route is read-only.

## Decision
Add `forge-server` as a Go standard-library command backed by an `internal/appserver` package. The caller supplies a canonical absolute non-root path for a dedicated state directory, bounded at 4096 bytes and 64 components before cleaning or filesystem access. Its existing direct parent is the filesystem trust anchor: it must be effective-user-owned and not group or world writable. The complete parent path is observed without symlink components before and after binding that parent identity; mapped owners must be root or effective user, non-sticky group/world-writable ancestors reject, and only the configured overflow UID when absent from every inside range of a Linux non-initial user namespace is treated as an explicit supervisor TCB. First use creates the state leaf with exact mode `0700`, an immutable version identity, and a single-link `0600` lock identity; an existing directory is accepted only when it is effective-user-owned and has exactly that versioned layout. A newly opened root or state file is closed immediately if its identity `Stat` fails, before any subsequent path lookup. Unknown entries, special mode bits, hard links, noncanonical paths, symlink path components, replaceable state parents, writable upper ancestors, and arbitrary pre-existing private directories fail closed without being chmoded or truncated.

On `GOOS=linux` with Android explicitly excluded, state operations remain relative to bound directory roots and the process takes an exclusive nonblocking advisory lock. Contention fails immediately and process exit releases the kernel lock. Every other target, including Android, AIX, Darwin, Illumos, Solaris and Windows, compiles but rejects startup before state access. Version 1 deliberately does not claim that mode bits capture independent ACL models on those targets and has no descriptor-bound validator for them.

The server accepts only a literal loopback IP and port. Port zero is allowed for tests and supervised startup. A missing embedding startup-receipt announcer is rejected before state or listener acquisition. The package exposes no route constructor; `Run` is the sole serving entry and owns listener setup, receipt publication, connection limits, request composition and HTTP timeouts. The command binds the socket, completes a bounded and cancellable JSON startup receipt, and only then starts accepting HTTP. It implements only `GET|HEAD /api/v1/health`; the exact listener authority is required in `Host`, the general `OPTIONS *` handler is disabled, and live connections and valid health requests have fixed caps. Host, path and method preflight always precedes valid-request saturation handling, so overload cannot replace an exact rejection with a generic busy response. The response contains the API version, service name, status and bounded build version and commit. It contains no path, uptime, hostname, project, prompt, credential, Runtime, Harness or product state. Unknown routes, authorities and mutation methods fail with versioned JSON errors, CORS is absent and defensive response headers are fixed.

Caller cancellation performs a bounded graceful shutdown, including while startup output is blocked. This version creates no `control.db`, discovers or reads no ambient workspace, reads no Runtime database, starts no Agent or provider, makes no outbound request and advances no state. It only inspects and initializes the explicitly supplied state path and its ancestors for filesystem security. Future product commands, projections, event ingestion, UI assets, authentication or remote binding require separate versioned decisions.

## Consequences
R0 gains a runnable local App Server seam with an independently testable lifecycle, dedicated instance namespace and stable health contract. Later clients can depend on one process startup receipt without reading implementation databases or parsing the existing low-level CLIs.

The first invocation must name a missing dedicated leaf; subsequent invocations require the exact v1 identity and lock files. A crash during first-time initialization may leave an incomplete directory that is rejected until the operator removes that dedicated leaf. The initial process is intentionally not yet useful for delivery work. It exposes no Space, Project, Objective, Attempt, Timeline, Decision, Artifact, Verification or Outcome API.

Existing Forge components remain independent. The new server does not become completion authority, approval authority, a Runtime controller or a Harness proxy merely because its process reports `ok`.

## Validation
Unit tests cover literal loopback and exact state-path byte/component boundaries, immediate handle closure on injected `Stat` failure, build identity bounds, exact health and error bytes, authority and method rejection before saturation, raw `OPTIONS *`, headers, missing CORS, valid-request and connection caps, private permissions, special mode bits, dedicated identity, unknown entries, symlink and writable ancestors, Linux UID-map classification, hard links, same-inode owner/mode ABA, lock contention and lock reuse. In-process integration rejects a missing announcer before state mutation, starts a real ephemeral loopback listener, proves HTTP does not respond before startup publication completes, performs a health request, and verifies bounded cancellation and announcement failure.

Linux process tests build and execute the real command, exercise cross-process lock contention and reuse, read the metadata-only receipt, request health, interrupt normal and pipe-blocked startup, and require bounded zero exit. A bad startup output descriptor must fail without serving. Build and lock-selection tests cover supported `GOOS=linux` plus fail-closed Android, AIX, Darwin, Illumos, Solaris and Windows targets. Full Go tests, formatting, architecture checks, governance checks and repository acceptance remain required before the Roadmap item can be marked complete. No live model, provider, credential or external network is used.

## Limitations
Health version 1 is liveness for one local process only. It does not check or attest Runtime, Harness, storage durability, disk capacity, project registration, provider access, Agent availability, workflow readiness or user Outcome. It has no authenticated principal and must not gain private or effectful routes by convention.

The lock depends on Linux `flock` semantics and a cooperating local filesystem whose effective access grants are represented by the checked mode bits. Linux POSIX ACL masks participate in those group mode bits; version 1 does not generalize that relationship to ACL models with independent grants, so Android and every non-`GOOS=linux` target fail before state access. Direct-parent owner and mode checks are repeated across pre-open, opened and post-open identities, including same-inode ABA. Higher namespace components reject mapped-untrusted owners and non-sticky writable directories, but all unmapped host principals collapse to the configured overflow UID and cannot be distinguished inside a Linux non-initial user namespace; all such principals, the supervisor, OS, root and any TCB able to remap an accepted direct-parent entry between separate startups remain trusted. The lock is not a hostile same-user fence, distributed lease, publisher attestation or tamper-resistant authority. A permanently blocked custom embedding announcer may retain one goroutine until that callback returns; the public command still exits on cancellation because process termination does not wait for it.

The listener is plain local HTTP, not TLS. Exact `Host`, no CORS, bounded connections and no private route reduce this v1 surface, but loopback binding is not a complete future browser-origin, CSRF, DNS-rebinding, local denial-of-service or multi-user isolation design.

Proposed status records an architecture candidate and its implementation evidence only. It is not an ApprovalRecord, authenticated adoption, compliance verdict, lifecycle promotion or permission to add subsequent App Server capabilities.

# ADR-0104: Workspace Catalog Application Service v1

## Context
R0-C1 provides a private canonical Control journal with optimistic aggregate heads, idempotent command results and bounded replay. The next planned forge-core task is FC-04: a Workspace application boundary for Space, Project and ProjectSnapshot catalog operations. Without that boundary, a future API would either encode product semantics directly in transport code or expose private SQLite tables.

The product design treats Space as a container and Project as a declared local catalog entry. Filesystem observation and snapshot capture require a separately reviewed observer port; merely accepting a path or RecordRef cannot prove repository identity, freshness, completeness or safety. Objective, Change and WorkGraph also have independent state-machine and completion risks and should not be bundled into this catalog slice.

## Decision
Add three isolated Go packages under forge-core/internal/workspace: domain owns immutable v1 Space, Project and ProjectSnapshot-reference entities and exact creation folds; application owns create/get/list use cases, canonical command and event construction, bounds, parent checks, source-sequence retry and stable application errors; store is an infrastructure adapter over internal/controlstore. Dependencies point from store to application and domain, and from application to domain. Neither inner package imports SQLite or App Server transport.

CreateSpace, RegisterProject and RecordProjectSnapshot each accept explicit Platform IDs, command metadata and expected version zero. The service validates command-specific fields, creates one exact forge.workspace canonical CommandEnvelope and one caused control_plane EventEnvelope, and commits an exact replayable result through the existing immediate transaction. Event identity uses a cryptographically random Platform ID source. A source-sequence conflict may rebuild the still-uncommitted event against a fresh durable head for a bounded number of attempts; exact command replay returns the first durable result and never appends a second event. Version, identifier, idempotency and corruption failures map to stable internal errors without claiming authorization.

A Project root is only a bounded UTF-8, canonical absolute lexical path with status declared_unverified. Registration performs no stat, open, Git discovery, language detection, secret scan or workspace read. A Project alias is a display token, not a uniqueness key in v1; ProjectID is identity. RecordProjectSnapshot does not capture anything. It stores an exact caller-supplied RecordRef with status declared_unresolved after structural Platform Core validation, and binds Space, Project and ProjectSnapshot IDs through ScopeRef. The actor is caller-declared metadata and is not authenticated.

Extend controlstore with bounded integrity-checked reads by aggregate stream while retaining schema v1. Those reads also verify and expose the originating canonical Command actor. Get operations fold one aggregate's contiguous canonical events, require Command/Event actor equality, resolve durable parents, and fail closed on unknown schema, payload, scope, actor, parent or version history. List operations reuse one-row global journal pages, consume at most 999 events plus one exact continuation lookahead, reload and fold each encountered target aggregate before output, filter by requested parent, and return an explicit global continuation cursor. Any list error returns no partial items. A filtered page may contain fewer entities than requested, including zero, while indicating that more journal data remains. Later mutable lifecycle events or larger scale require a versioned fold and rebuildable projection rather than silently widening bounds.

This slice exposes only an in-process application API. It does not wire a public HTTP, SSE, WebSocket, CLI or TUI route and does not change health semantics. It adds no local login, cookie, bearer token, origin policy, Grant, Approval, Objective, Change, WorkGraph, Reconciler, Runtime/Harness transport, outbox worker, projection table or UI.

## Consequences
The Go control plane gains its first real product-domain consumer of the canonical journal. Space, Project and declared Snapshot references can survive restart, use exact command idempotency, reject stale creation and be reconstructed without granting clients SQL access. Future transport code can depend on an application API rather than embed persistence decisions.

Schema v1 remains unchanged and rollback requires no database migration. The tradeoff is intentionally bounded event replay and filtered journal scans. This is suitable for the R0 catalog but is not a scalable Space overview or query projection. Continuation and scan exhaustion remain visible instead of being reported as a complete list.

The durable schema, Platform Core wire and public health surface remain compatible. The unconsumed `internal/controlstore` Go source API is intentionally revised: three location-specific identifier-conflict sentinels are consolidated as `ErrIdentifierConflict`. Source rollback must restore the old sentinel names and adapter tests together; this is not a Go source-compatibility promise.

Persisted paths and observation references are declarations. They do not establish that a path exists, is a Git repository, belongs to the caller, has not changed, contains no secrets or corresponds to the referenced observation. Random event IDs provide uniqueness, not authority or authentication.

## Validation
Pure domain and application tests cover exact creation folds, unknown or duplicate creation history, aggregate and scope mismatch, payload key/type drift, bounds, Unicode, path lexical rules, alias tokens, RecordRef structure, missing parents and expected-version zero. A production-import allowlist prevents the Workspace domain, application and adapter from gaining filesystem, process, network or alternate infrastructure dependencies; an integration sentinel separately confirms that registration does not create the declared path. Tests also verify that event causation, correlation, source sequence, actor, schema and replayable result are derived exactly.

Linux adapter tests use the real descriptor-bound control.db to create, get and list each entity, replay an exact command across reopen, reject same-key different-command and same-ID concurrent creation, preserve parent filtering and cursor progress, and fail closed on canonical but semantically invalid Workspace events. Focused race tests cover concurrent callers and sequence contention. Existing Control Store recovery, corruption and startup suites remain green because no schema changes.

Repository validation requires formatting, focused and full Go tests, race, vet, CGO-disabled and fail-closed cross-builds, module verification, architecture, gate and governance checks, independent fresh-context architecture/storage review and formal forge acceptance. No provider, credential, Runtime process, Harness execution, project file, external network or user browser is used.

## Limitations
The service creates immutable v1 catalog entities only. It cannot rename, archive, delete, rebind or verify a Space or Project, enforce alias or path uniqueness, select a current Snapshot, or express project membership authorization. Any such behavior requires versioned commands, event folds and cross-aggregate ownership rules.

List is a bounded event-backed repository query, not a projection. It offers cursor-safe progress through the inspected global journal but does not promise a materialized, total-count, arbitrary-sort or full-text view. A later projection must be rebuildable from exact events and prove cursor and delete/rebuild parity.

No Objective, AcceptanceCriteria, Change, WorkGraph, WorkItem, Attempt, Verification or Outcome behavior exists here. There is no user-facing operation and therefore no complete Objective-to-Outcome path. App Server health remains only a process-serving signal after storage validation.

Proposed status records an exact candidate decision and its implementation references. It is not authenticated adoption, an ApprovalRecord, authorization, filesystem evidence, product readiness or permission to expose private state.

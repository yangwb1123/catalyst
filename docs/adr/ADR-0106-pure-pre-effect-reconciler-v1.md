# ADR-0106: Pure Pre-Effect Reconciler v1

## Context
ADR-0105 supplies bounded Objective, Change, WorkGraph and WorkItem values, deterministic DAG validation, and caller-supplied snapshot comparison, but intentionally leaves FC-06 ready-node selection open. The target architecture assigns top-level selection to the Go Reconciler and requires the same complete observed state to yield the same next decision without performing I/O.

The broader implementation plan groups effective Policy and Approval, budget consumption, Attempt dispatch, Runtime transport, Harness verification, completion joins, manual override, retry and recovery under F6 and F7. Those capabilities currently lack a durable atomic Delivery projection, independent WorkItem version, authenticated general-effect authority, budget reservation, RuntimePort, VerificationPort, Receipt freshness policy, and crash-recovery transaction. Producing DispatchAttempt or completion decisions now would give names of authority to caller declarations that cannot support them.

The repository also contains scheduled-graph and legacy orchestration reconcilers. They bind different Run, schedule, node, lifecycle and effect contracts. Reusing them would make a compatibility protocol the accidental Objective and WorkGraph product owner.

## Decision
Create forge-core/internal/reconcile/application as one pure application policy over forge-core/internal/delivery/domain. `Decide` consumes a complete caller-owned `ControlSnapshot`, revalidates Objective-to-Change-to-WorkGraph relations, validates supplied current snapshot identifiers, exact version-bound WorkItem assessments and predecessor progress, then returns exactly one deterministic Decision or one stable invalid-snapshot error.

Freeze six passive Decision kinds: NoOp, AwaitApproval, ReadyWorkItem, BlockWorkItem, ReplanChange and EscalateUncertain. Each valid Decision binds Objective, Change and WorkGraph identifiers and versions, an optional WorkItem target represented by an empty or exact ID, a stable reason code, and copied sorted structural evidence references. ReadyWorkItem is only the first deterministic pre-effect candidate; no Decision requests a state edge or releases authority.

Assessments use one closed authority-neutral status vocabulary for declared Policy, Approval and Budget conditions: unknown, satisfied_declared, unsatisfied_declared and uncertain. An assessment binds one exact WorkItem, Change version, WorkGraph version, policy profile, ProjectSnapshot, risk and requested-effect set, with one to sixteen unique structurally valid RecordRefs. Missing assessment coverage is permitted but stops the selected candidate. The package never authenticates a status or resolves evidence.

Decision precedence is fixed: structural validation, including exact parity with Platform Core's current WorkItem state vocabulary and bounded assessment identifiers and effect declarations before lookup or sorting; uncertain Change, WorkItem or assessment; supplied snapshot drift; inactive aggregate lifecycle; in-flight WorkItem; terminal blocker; first lexicographic-topological dependency-ready candidate; Policy then Approval then Budget; finally all-completed-unjoined NoOp. A validated active DAG with incomplete work must have a dependency-ready minimal item; failure of that invariant, impossible progress, mixed versions, or an upstream state-vocabulary change is invalid input rather than a business NoOp. Precondition state cannot cause the selector to skip an earlier candidate.

Allow this package as the exact sole production consumer of the mutable Delivery Domain, and admit no production consumer of its Decisions in R0-C4. Its production imports remain limited to pure standard library packages, Delivery Domain, Platform Core references, and Platform Core state vocabulary. Add no I/O, persistence, controller loop, canonical wire, identity or time generation, authenticated authority, transition, Attempt, dispatch, Receipt, completion, API or UI.

## Consequences
The Go control plane gains a single reviewable owner for deterministic top-level pre-effect selection. Equivalent graph and assessment permutations have one decision, uncertainty and stale supplied snapshots take explicit priority, missing or denied preconditions fail closed, and in-flight or terminal work cannot cause a second candidate to be released.

The output vocabulary is intentionally not the final target Decision algebra. DispatchAttempt, RequestVerification, CompleteWorkItem and CompleteChange remain unavailable until their required effect and completion boundaries exist. A future effectful consumer must revisit this ADR and may replace passive candidates with durable state-transition requests under current-version and authority checks.

The Delivery Domain's prior zero-consumer proof changes to an exact one-consumer allowlist. This is an intentional ADR-0105 revisit, not a relaxation for arbitrary application, legacy, Runtime, Harness, CLI or testdata importers.

## Validation
Table tests must reach all six Decision kinds and each stable reason family, verify exact precedence, reject contradictory progress, mixed versions, declaration substitutions, duplicate and unknown assessments, invalid evidence, and values beyond every new bound. The selector must cover root, successor, diamond, multiple-frontier, draft frontier, uncertain predecessor, in-flight, terminal blocker, missing approval, denied policy, exhausted budget, supplied snapshot drift and all-completed cases, and its impossible no-frontier fallback must fail closed as invalid input.

Deterministic tests must permute WorkItems, dependency declarations, current snapshot bindings, assessments, requested effects and evidence, repeat calls, and run parallel race-enabled calls over a stable input. Results must be deeply equal, input must remain unchanged, and output evidence must not alias input storage.

Boundary tests must permit only forgeos/forge-core/internal/reconcile/application to import Delivery Domain, reject every production consumer of the Reconciler, restrict its production imports to the reviewed pure closure, and reject filesystem, process, clock, random, database, network, control-store, Runtime, Harness, graph-legacy and orchestration capabilities. Focused and full Go normal and race tests, vet, build, supported cross-platform compile, format, module, architecture, governance, fresh architecture/domain and reliability/security review, and formal repository acceptance must all pass before the R0-C4 completion marker is retained.

## Limitations
The caller is responsible for supplying one complete stable race-free value graph. Validation does not create an atomic snapshot, authenticate its producer, observe the current repository, resolve RecordRefs, or prove freshness, truth, approval, permission, budget availability, or durability. Equal ProjectSnapshot IDs are only equal supplied identifiers.

The package performs one pure call and returns at most one passive candidate. It has no current-state fold, independent WorkItem version, CAS, journal, outbox, controller worker, retry, resume, manual override, concurrency wave, conflict analysis, RuntimePort, provider, Attempt, VerificationPort, Harness check, Receipt join, Artifact resolution, completion policy, Outcome, or Change completion.

Passing this slice closes only the FC-06 pure pre-effect selection subset. It does not close the broader F6 or F7 milestones, FC-07 or FC-08, F3 or F4, the R0 single-WorkItem vertical journey, R0 Developer Preview, Objective-to-Outcome delivery, or the final target Reconciler contract.

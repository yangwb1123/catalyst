# ADR-0078: WorkIntent v1 Proposed Candidate Governance and Source Distribution

## Context
ADR-0077 defines an authority-neutral WorkIntent v1 Proposed semantic candidate and records exact Python, Go and Rust parity evidence. It deliberately does not decide registry placement, governance activation, scaffold distribution, routing, persistence or runtime consumption. The three-language evidence therefore needs a separate, equally Proposed governance decision before the candidate can be referenced by the shared Registry or copied into generated projects.

The integration must preserve the distinction between structural evidence and operational authority. A valid caller-supplied declaration does not authenticate origin, requester or declared owner; resolve references; determine freshness, materiality or scope; close G0; create a Run, RunJournal or lifecycle; approve or permit work; choose a route; persist state; or execute an effect. Candidate metadata and a successful checker cannot promote any of those unavailable semantics.

Generated projects need only the portable Python validation sources and their exact artifacts. Copying the Catalyst Go or Rust candidates, inventing a portable Skill or adapter, or creating a runtime consumer would expand the decision beyond source-only structural verification.

## Decision
Propose Registry v32 candidate-only metadata for the unchanged `forgeos.work-intent/v1` contract. The Registry binds the ADR-0077 decision, Schema physical SHA-256 `3b02fab59eae8767c86caaa73d0830adcbd92825045b7f27db0c3eca5ee10e01`, golden physical SHA-256 `8e80553677ebf9f6548a15be4c3cb4ccc8aa6825010a20f2e890e91d1cd7ed7b` and canonical record digest `2fe0424d30405a8b1d716afc99bbd38d602375f3316fd1c54c472890d520a225`. It records Python, Go and Rust candidate implementations with exact golden parity, but classifies none as accepted semantic authority.

The complete Registry `scope` mapping remains byte-semantically unchanged from v31. WorkIntent is not added to shipped or planned kinds, projections, adapters, producers, projectors, evaluators, runtime profiles or persistence. Registry v32 adds no route, runtime binding in the operational sense, evaluator, producer, consumer, lifecycle, Approval, Grant, permission, persistence, execution or effect.

Add one checker-only shadow, non-load-bearing detector that runs `python3 harness/work_intent_contract_check.py --golden repo_root`. The detector verifies the exact structural candidate and does not author, evaluate, produce, consume, route or persist WorkIntent. Activation references point only to the Schema, golden, checker, ADR-0077 and this decision. The contract discipline lists the Schema and checker. Every WorkIntent reference remains absent from authenticated context routes.

Source-only fresh and legacy scaffold distribution copies the exact Python semantic core and checker, Schema, golden, ADR-0077, ADR-0078 and WorkIntent governance module and test. It does not copy the Catalyst Go or Rust implementations, install a host Skill, create a portable package or adapter, or add a route or runtime consumer. Source distribution is evidence of available validation sources only, not acceptance, activation or authority.

Documentation may mark only the narrow Wave 0 Proposed candidate evidence bullet complete. The parent `change-intake-orchestration` package, its remaining 31 items and G0 remain open. This decision does not claim that the functional WorkIntent or orchestration requirement is accepted or shipped.

## Consequences
The shared Registry and Agent Engineering checks gain one exact, mutation-tested description of the WorkIntent v1 Proposed candidate. The physical artifact pins and three implementation references make parity evidence visible without changing the semantic contract bytes or operational scope.

Fresh and legacy generated projects can run the exact Python golden checker and governance regression sources without receiving Catalyst-only language implementations. Copy parity is a source-distribution property; it does not authenticate the source, provide atomic check-to-use guarantees or establish runtime availability.

The policy version and physical digest change even though runtime scope does not. Future work must not interpret that administrative version change, detector success or source presence as acceptance, semantic authority, G0 closure, routing, permission, persistence, execution or effect.

## Validation
Validate ADR-0077 and ADR-0078 with the strict ArchitectureDecisionRecord v2 checker and compare their body, self and physical pins. Re-run the unchanged Python, Go and Rust WorkIntent focused suites and require exact Schema, golden and record identity parity.

Mutation-test Registry v32 candidate metadata, canonical references, artifact pins, implementation placements, non-capability text and the complete unchanged `scope` mapping. Reject every attempt to enable an authority semantic, classify WorkIntent in a scope array, change a pin or substitute a distributed Go or Rust implementation.

Run Agent Engineering checks for the exact activation references, Schema and checker discipline assets, checker-only shadow detector and WorkIntent absence from every authenticated context route. Detector success must remain the exact ADR-0077 structural-only marker.

Run source-only fresh and legacy scaffold checks in generated trees. Require exact copied Python, Schema, golden, ADR and governance bytes, focused checker success and no copied Catalyst Go or Rust WorkIntent directory, portable Skill, adapter, route, runtime consumer or authority infrastructure.

Run focused governance, agent, repository check, gate and architecture checks without the long suite. Verify the roadmap changes only the Proposed candidate evidence bullet and leaves `change-intake-orchestration`, G0 and the remaining 31 package items open.

## Limitations
This decision does not accept ADR-0077 or ADR-0078 and does not make either one semantic authority. It does not authenticate a caller, origin, requester, owner, repository, publisher, host or interpreter. It does not resolve a claim, evidence, artifact or snapshot reference, assess freshness, materiality or scope, or infer missing intent.

The checker does not create or consume operational work. No WorkIntent kind is registered as shipped or planned runtime scope; no authenticated route, evaluator, producer, consumer, Run, RunJournal, lifecycle, Approval, Grant, permission, persistent store, execution or effect exists under this decision.

Source-only distribution is not a portable Skill or package, host installation, trusted delivery channel, signature, sandbox or atomic check-to-use protocol. Go and Rust remain Catalyst-repository candidate evidence and are not scaffolded. Any runtime integration, authority promotion, broader packaging or contract-byte change requires a separate versioned decision and evidence.

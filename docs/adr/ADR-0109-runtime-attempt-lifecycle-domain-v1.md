# ADR-0109: Runtime Attempt Lifecycle Domain v1

## Context
R0-C5 and ADR-0107 delivered only an immutable `AttemptRequest` whose derived state is `requested`. Platform Core already owns the open Attempt state vocabulary and the exact thirteen legal edges, but its validator deliberately checks only a supplied edge and does not own a current Runtime value. FR-03 therefore still lacks a small domain value that can apply the frozen graph without claiming durable state.

The next dependency after FR-03 lifecycle is FR-04, which decides when a durable Attempt aggregate is created and owns identity, current-version authority, journal, outbox and recovery. Adding those concerns now would combine a pure state decision with storage and crash semantics. Adding Session, Turn, Action, a StartAttempt wire or a Go consumer would similarly cross later boundaries before this value is independently testable.

ADR-0107 also freezes the `execution::attempt` module and its `AttemptRequest` API as lifecycle-free. The new value must therefore be a sibling module and must not weaken the existing source inventory or no-consumer proof.

## Decision
Add `execution::attempt_lifecycle` with an immutable private-state `AttemptLifecycle`. The only seed is the explicit `requested()` constructor; there is no `Default`, raw `AttemptState` constructor, `From` conversion or `AttemptRequest` consumer. `state()` returns only an immutable reference.

Define a closed `AttemptTransitionRequest` with exactly seven variants: `Accept`, `BeginStarting`, `ObserveRunning`, `ObserveInterrupted`, `ObserveCompleted`, `ObserveFailed` and `ObserveEffectOutcomeUncertain`. The last variant is the only route to Platform Core `uncertain`; its name means only that the caller declares an effect may have started and its outcome is unproved. It does not authenticate that declaration or retain evidence.

`reduce()` deterministically maps one request to one known target and delegates every edge decision to the existing `validate_attempt_transition`. It never copies the edge graph, changes the current value, treats an illegal same-state request as idempotent success, or maps a rejection to `failed` or `uncertain`. Success returns a new owned lifecycle value. Platform Core `TransitionInvalid` remains the exact rejection family because the public lifecycle and request types make unknown states and requests unconstructible.

Add no Attempt identity, aggregate version, expected version, journal position, event, receipt, retryability, budget reservation or usage. Add no serde, wire, digest, schema, database, clock, randomness, filesystem, process, network, provider, tool, Harness, Go or user-interface dependency.

## Consequences
The Rust domain can now represent and deterministically advance one authority-free Attempt lifecycle through exactly the Platform Core graph. Terminal closure, forbidden fast-forward, absence of reset and explicit uncertainty intent become locally testable without choosing persistence or transport semantics.

The lifecycle value intentionally retains only its state. A later FR-04 aggregate must persist the transition request and its actual observation evidence before treating any result as current durable state. Reconstructing a lifecycle from storage is not part of this API and requires that later decision.

`AttemptRequest` remains an immutable declaration and gains no transition method or production consumer. Passing this slice closes only FR-03b; Session, Turn and Action keep FR-03 open, while FR-04, FR-06 and FC-07 remain fully open.

## Validation
Exhaustively construct all eight known lifecycle states through legal request sequences and evaluate each against all seven request variants. The matrix must accept exactly the thirteen Platform Core edges and reject the other forty-three pairs with `TransitionInvalid`. Each terminal state must reject every request; same-state, backward, reset, retry, reopen and fast-forward attempts must never succeed.

Test repeated and parallel calls for equal values and errors, successful and rejected reductions for failure atomicity, clone/equality stability, and every state applicable to `ObserveEffectOutcomeUncertain`. The API inventory must prove the state field is private, construction begins only at `requested`, the request enum is closed, and no generic target or Uncertain constructor exists.

A separate source boundary must pin the lifecycle source and public API, allow only Platform Core `AttemptState`, `PlatformCoreContractError` and `validate_attempt_transition`, reject external dependencies and ambient/effect identifiers, and scan for unreviewed consumers. Existing R0-C5 hashes and API checks must remain unchanged. Run focused tests, all domain and workspace targets, build, formatting, strict Clippy, architecture, governance, fresh-context dual review and formal `node harness/acceptance.mjs` on one frozen tree.

## Limitations
Every transition request is a caller declaration. The reducer does not authenticate an observer, prove an effect started, resolve evidence, read current durable state, compare expected version, reserve budget, append an event, issue a receipt, authorize execution, change a WorkItem, retry an Attempt or determine completion.

The closed request enum is a Rust source API, not a versioned wire. Unknown future operations are intentionally unrepresentable here; FR-06 must define their decode and compatibility behavior before crossing a process boundary. The use of Platform Core error codes does not make the lifecycle a Platform Core-owned current state.

There is no direct constructor for `accepted`, `starting`, `running` or any terminal state. This keeps invalid and unsupported states out of the value today, but means FR-04 must revisit checked restoration rather than bypass privacy. No terminal state can reopen; retry requires a separately identified future Attempt.

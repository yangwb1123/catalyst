# ADR-0090: Kernel Decision Reference Core v1

## Context
ADR-0088 freezes the five operational reference records needed below a complete Kernel ABI, but it intentionally omits the cognitive and decision layers. The remaining structural gap is an exact CognitiveAtom source, type, authority and hardness envelope plus an immutable DecisionTransaction that binds predecision atoms to the ADR-0088 operation graph without introducing a cycle.

Existing ADR-0047 CognitiveAtom, ADR-0060 EvidenceRef and ADR-0077 WorkIntent shapes are reusable only at exact reference boundaries. ADR-0047 `atom_id` is not derived from its `canonical_sha256`; ADR-0060 `record_id` is bounded text rather than an identifier. Runtime Run, Command, Transition, Approval, Grant and persistence records carry meanings that cannot be aliased into a decision proposal.

Declared authority and hardness are especially easy to overread. This structural ABI must preserve the caller's declarations for future promotion, while making them ineffective now. A complete structural shape therefore does not imply a policy decision, authenticated authority, hard guard, instruction, authorization, execution or persisted decision.

## Decision
Adopt exact `CognitiveAtom` v2, `DecisionTransaction` v1 and one nonsemantic `KernelDecisionReferenceClosure` v1. The closure embeds the exact ADR-0088 `KernelOperationalReferenceClosure`; Python calls its validators directly, and Go and Rust call the public ADR-0088 closure validators. This dependency is one way. No ADR-0088 wire or validator is copied, widened or reinterpreted.

`CognitiveAtom` has exactly nineteen fields: `api_version`, `atom_id`, `atom_sha256`, `atom_type`, `attestations`, `bindings`, `canonicalization`, `confidence_micros`, `declared_authority`, `declared_hardness`, `effective_hardness`, `epistemic_state`, `instruction_allowed`, `kind`, `proposition`, `scope`, `source`, `task_binding` and `validity`. Its sixteen types are acceptance, actor, assumption, constraint, decision, evidence, fact, goal, hypothesis, inference, object, observation, operation, preference, risk and unknown.

Proposition is the exact ADR-0047 four-field shape. An `artifact_ref` object value uses the frozen identifier grammar; a `string` object value is bounded nonempty text. Boolean, signed-int64 integer and null values retain their JSON types. Scope has exactly `project`, `module` and `object`. Project is nonempty short text and equals `task_binding.project_id`; module and object are null or nonempty short text; a nonnull object equals `proposition.subject`. These are caller-declared internal equalities only. They do not resolve a project, module or object and make no completeness claim.

Source has exactly `source_kind`, `source_phase`, `source_ref` and nullable `source_selector`. Predecision sources are artifact, ADR-0047 cognitive atom, ADR-0060 evidence record and WorkIntent. Postdecision sources are ADR-0088 ArtifactReceipt, CapabilityInvocation, InteractionEvent and ExecutionReceipt. A nonnull selector is a canonical nonempty RFC 6901 pointer of at most 4,096 UTF-8 bytes; a legacy atom selector is null. Source/type admission is frozen by the validators and Schema shadow. The ADR-0047 legacy reference independently validates `atom-[0-9a-f]{64}` and a bare canonical digest without requiring equality. EvidenceRef `record_id` is exact short text, including text that is not an identifier.

Declared authority has exactly `authority_kind` and `authority_ref`. Kinds are none with null ref, exact ADR-0059 ApprovalRecord ref, ArchitectureDecision ref with `adr_id` and `adr_self_sha256`, or exact ArtifactRef for a contract artifact. Declared hardness is type-specific: acceptance and goal admit advisory, preferred or required; actor, evidence, fact, object, observation and operation admit none; constraint admits advisory, contract, invariant, preferred or required; decision admits advisory or required; preference admits advisory or preferred; and assumption, hypothesis, inference, risk and unknown admit advisory or none. Contract and invariant require contract-artifact authority, required requires nonnone authority, and a required Decision requires an ADR or Approval. Legacy atoms preserve none authority and hardness. Confidence is present only for assumption, hypothesis and inference and is zero through one million micros.

Every atom freezes `effective_hardness` to `none` and `instruction_allowed` to false. Every atom, transaction and outer closure has exactly twenty-two false attestations: approval authentication, authority, authorization, binding authentication, CAS, completion, content provenance, effect, event append, execution, Grant authentication, hard guard, instruction, outcome, permission, persistence, principal authentication, source resolution, transition, truth, usage measurement and verifier independence. Hard or authority-bearing promotion is outside this decision and belongs to later authority and promotion work.

`DecisionTransaction` has exactly twenty-seven fields listed by the Schema and three implementations. It reuses exact ADR-0056 Principal, TaskBinding, CapabilityIdentity and Budget value semantics and ADR-0088 bindings and ArtifactReceiptRef. It declares one goal atom, zero through sixty-four trigger atoms, zero through sixty-four guard atoms, one through sixteen options, one through thirty-two proof obligations, zero through thirty-two reads, write preconditions and write slots, a selected option, accountable owner, actor, independent declared verifier, completion condition, optional compensation, idempotency key and creation time. Atom roles are disjoint; their arrays are strict identity-sorted and unique. `transaction_mode` is exactly `structural_proposal_only`.

The transaction is an immutable proposal, not a Grant, Approval, policy decision, status, result, receipt or execution record. Every ADR-0088 invocation must use the selected option capability and requested-action digest, transaction actor, idempotency key, reads and write slots. Invocation, Event and ExecutionReceipt correlation IDs equal the transaction ID. The verifier differs from actor and accountable owner, but verifier independence remains unattested.

The digest DAG is external source or declared input, then predecision atoms, then DecisionTransaction, then ADR-0088 operational records, then postdecision atoms, then ADR-0088 closure, then outer closure. A transaction references predecision atoms only. Every predecision atom is in exactly one goal, trigger or guard role; every role resolves exact atom ID and digest. Postdecision refs resolve an exact included operational record. An ArtifactReceipt source must be `declared_output`, never a genesis declared input. Postdecision validity begins no earlier than both transaction creation and source time. Predecision validity covers transaction creation. These edges are one way; no atom or transaction back-reference is added to ADR-0088 records.

Every atom and every ADR-0088 record carries exactly the transaction TaskBinding and opaque bindings. This prevents a predecision atom from another task or source snapshot driving the transaction. Transaction reads resolve exact nonfuture declared-input receipts. Every invocation count is independently at most `budget.max_calls`. In addition, each of the seven caller-declared usage fields is summed across every ExecutionReceipt with checked signed-int64 addition and compared with its transaction limit. These are caller declarations, not measured or cumulative authoritative usage.

Atom, transaction and outer identities hash compact canonical JSON with identity fields empty after NUL-terminated domains `forgeos.aadm.cognitive-atom.v2`, `forgeos.aadm.decision-transaction.v1` and `forgeos.kernel-decision-reference-closure.v1`. Prefixes are `cognitive-atom-`, `decision-transaction-` and `kernel-decision-reference-closure-`. Ceilings are 128 KiB per atom, 1 MiB for the atom set, 1 MiB for the transaction and 20 MiB for the outer closure. Shared wire limits remain depth sixteen, sixty-four fields, 256 array items, 16 KiB strings, 160-byte short text, 4,096-byte references and signed-int64 integers.

Python, Go and Rust expose pure canonical, decode, seal and validate APIs and reproduce one physical LF-framed golden. The Python checker accepts one explicitly named single-link regular no-follow file or the pinned golden. It writes only the exact structural marker on success and writes no stdout on rejection. The Schema is a structural shadow; runtime validators are the load-bearing accept set.

## Consequences
The repository gains a complete structural Kernel ABI closure over CognitiveAtom, DecisionTransaction and ADR-0088 operational records. Callers can reproduce exact identities and detect cross-task, cross-source, selection, time, budget and reference drift without a runtime PDP, authority service, database, event append or capability route.

Declared authority and hardness remain visible for compatibility, but are deliberately ineffective. The outer success marker says only that exact caller-supplied structural relations close. It does not say any proposition is true, any source or principal is authentic, any Approval or Grant is valid, any guard is hard, any instruction is allowed, any operation is authorized or executed, or any result is persisted.

After this core and its separate governance/source-distribution decision have exact three-language parity and independent cross-closure review, the roadmap item for the full structural Kernel ABI may be honestly closed. That closure must not mark Governance authority kernel, active promotion or runtime policy enforcement complete.

## Validation
The golden pins physical SHA-256 `93f6225b745eacf966796cb671d723440890ae3ab02699dd40d6a078f539af1c` and outer closure digest `cdadf0e5fddbbda429939be4e68dc77dd0b52c0bb7e4fe955f1d485183908e58`. It covers all sixteen atom types, eight source kinds, six hardness values, four declared-authority kinds, seventeen atoms, two attempts and all four postdecision source kinds. Every atom, transaction, ADR-0088 record, ADR-0088 closure and outer closure is resealed against the same bytes in Python, Go and Rust.

Matching positive tests cover exact nineteen fields, twenty-two false attestations, nullable scope, the real non-equal ADR-0047 ID and digest, non-identifier ADR-0060 record text, empty I/O, zero triggers, two-receipt exact aggregate budgets and the complete retry graph. Target-specific N-plus-one tests cover 257 atoms, 65 trigger and guard refs, 17 options and evidence kinds, 33 proofs, reads, write preconditions and write slots, a 4,097-byte selector, the atom, aggregate atom-set, transaction and outer document ceilings, independent invocation count and all seven aggregate budget dimensions.

Matching ADR-0090 adversarial tests reject missing, unknown, duplicate, reordered and ill-typed fields; invalid UTF-8, controls, C1, bidi, isolated surrogate and noncanonical wire bytes; illegal artifact proposition identifiers; source/type/authority/hardness mismatches; ineffective-field promotion; unresolved, duplicate and orphan atom roles; postdecision declared-input refs and precreation validity; task and binding drift for atoms and every ADR-0088 record class; selected capability, action, idempotency, reads and writes drift; all three correlation edges; transaction/source temporal drift; and checked aggregation overflow. The outer validators directly invoke frozen ADR-0088 validators, whose separately frozen matching corpus remains load-bearing for retry, sequence, causation and operational time/order; this slice does not relabel those cases as new ADR-0090 tests.

Run focused Python tests with bytecode disabled, Go tests, race, vet and formatting, and Rust offline tests, formatting and lint. Validate the Draft 2020-12 Schema against the golden, validate this ADR as exact ADR v2, run architecture and file-integrity checks, verify all owned files are mode 0644 single-link regular files, and verify no Python cache remains. Independent semantic review is required before calling the core frozen.

## Limitations
This decision introduces no capability, product command, runtime adapter, PDP, authority issuer, promotion engine, event writer, persistence store, network service, Registry entry or scaffold distribution. It reads no ambient state and performs no action. It does not authenticate sources, principals, ApprovalRecords, Grants, contracts, bindings, verifier independence, results or usage.

The exact same-task and same-binding rules compare caller-declared bytes. They do not prove that the declarations are complete, current or genuine. Source selectors are syntax-checked but not evaluated. An exact operational reference remains an ADR-0088 structural receipt, not evidence that the operation occurred.

The structural full-ABI roadmap item remains open while this core lacks its governance/source-distribution decision and independent review. Governance authority kernel and hard or authority-bearing promotion remain separate later roadmap work regardless of structural ABI closure.

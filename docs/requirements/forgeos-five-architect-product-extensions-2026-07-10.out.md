## 文档核心论点摘要

这篇分析站在 93+ 份已有文档的肩头，通过差异化验证找出了**五个未被作为独立系统性方向展开的桥梁型缺口**：

| 方向 | 核心命题 | 优先级 |
|------|----------|--------|
| **① 二进制生命周期** | Forge 自身没有发布渠道、版本号、升级路径——一个宣称 24h 自治运行的系统无法自治更新自己 | 🔴 P0 |
| **② 工作区状态隔离** | `.forge/trace.jsonl` / `checkpoint.json` / `memory.jsonl` 是扁平共享命名空间，并发运行产生静默数据损坏 | 🔴 P0 |
| **③ 错误信息质量** | 三种错误构造方式混杂，无 `--json` 输出，无错误码目录，CI 集成只能靠 grep 文本 | 🟡 P1 |
| **④ 并行执行就绪度** | `RunParallel` 已交付但 loop-back 被禁用、8 把 mutex 的锁顺序无机器执法、无资源自适应、无锁竞争可观测性 | 🟡 P1 |
| **⑤ 测试基础设施** | 无共享 testutil 包、无 golden file 框架、时间不注入、harness 测试在真实工作区运行有 flaky 风险 | 🟡 P1 |

文档特别强调了每个方向与已有分析的**差异点**（例如方向②从「并发安全/状态污染」而非「可追溯性」切入），并提供了精确到 `file:line` 的代码证据和边界场景。
